Agent 进化论（四）：实战：手把手教你写第一个“会看天气”的自定义 Skill ​

前言：从“理论家”到“架构师” ​

诸位看官，且请满饮此杯。在 [上一篇](file:///Users/rs/Qsync/VSCodeProjects/MyProjects/techchangelife-rs.github.io/blog/source/_posts/agent-evolution-3-skills.md) 中，我们已经搞清楚了 Skills 的底层逻辑——Function Calling。

但理论听得再多，也不如亲手敲几行代码来得实在。很多同学可能会觉得，给 AI 写技能是不是需要掌握什么高深莫测的算法？或者需要成百上千行的代码？

今天，我就要打破这个迷思。我们将用最通俗的语言、最精简的代码，手把手带你完成一个 Agent 技能开发的“全流程”。

我们将要做的，是一个名为 get_weather 的天气查询技能。通过这个实战，你将亲眼看到：AI 是如何读懂你的意图，并精准地调用你的代码的。

第一步：定义 (Define)——给 AI 写一份“说明书” ​

在开发 Skills 时，最关键的不是写代码，而是写说明书。

这份说明书告诉 AI：

  • 这个工具叫什么？
  • 它有什么用？
  • 它需要哪些参数？

在 2026 年，最通用的说明书格式就是 JSON Schema。

1.1 核心代码拆解 ​

json
{
  "name": "get_weather",
  "description": "查询指定城市的实时天气和温度信息。仅在用户明确询问天气时调用。",
  "parameters": {
    "type": "object",
    "properties": {
      "city": {
        "type": "string",
        "description": "城市名称，如：'上海'、'北京'。"
      },
      "unit": {
        "type": "string",
        "enum": ["celsius", "fahrenheit"],
        "description": "温度单位，默认为摄氏度。"
      }
    },
    "required": ["city"]
  }
}

划重点：

  • Required：告诉 AI，没给“城市”参数，你绝对不能乱跑。

第二步：实现 (Implement)——编写真实的“行动逻辑” ​

有了说明书，接下来我们要写一段真实的 Python 代码。为了演示简单，我们先用一段“模拟数据”，但在真实场景中，你会在这里调用像和风天气或 OpenWeather 的 API。

2.1 极简 Python 实现 ​

python
import json

def get_weather(city, unit="celsius"):
    """
    这是技能的真实执行逻辑。
    """
    # 模拟 API 返回数据
    # 在真实场景中，这里会发送一个 HTTP 请求
    weather_data = {

第三步：注册 (Register)——把“手”接在大脑上 ​

现在，我们要把“大脑（LLM）”和“手（代码）”连接起来。不同的 Agent 框架（如 LangChain, CrewAI 或 MCP）注册方式不同，但逻辑是一致的：告诉大脑，这个工具你可以用。

3.1 核心逻辑模拟 ​

python
# 1. 准备好工具库
tools = [get_weather_definition] # 也就是第一步写的 JSON Schema

# 2. 发起对话
user_prompt = "帮我查下上海的天气怎么样？"

# 3. 大脑决策
# LLM 会识别出意图，并返回：Action: get_weather, Args: {"city": "上海"}
response = llm.chat(user_prompt, tools=tools)

# 4. 自动执行
if response.has_tool_call:
    # 执行我们写的 Python 函数
    tool_output = get_weather(**response.tool_args)
    
    # 5. 反馈给大脑
    # 大脑拿到 tool_output 后，会生成最终的自然语言回答
    final_answer = llm.chat(tool_output)
    print(final_answer)

第四步：测试 (Test)——见证奇迹的时刻 ​

当你把一切跑通后，奇迹发生了。

  • 输入：“上海冷吗？”
  • 大脑思考：用户问冷不冷，其实是想查温度。匹配 get_weather 技能。
  • 调用结果：获取到“上海温度 22 度”。
  • 最终输出：“上海现在 22 度，晴转多云，体感还是比较舒适的，不算冷哦！”

看！AI 不再只是在“复读”训练数据，它是在根据你的代码反馈，实时地回答问题。

避坑指南：给初学者的三条建议 ​

  1. 别让 AI 猜参数：如果一个参数是必须的，一定要在 Schema 里写清楚。否则 AI 可能会瞎编一个参数传给你。
  2. 错误处理要优雅：如果用户查了一个不存在的城市，你的函数应该返回一个友好的错误信息（如“抱歉，我暂时不支持查月球的天气”），而不是直接让程序崩溃。
  3. 描述词要“抠门”：不要写太长、太宽泛的描述。越精准，AI 误触发的概率就越低。
