各位大朋友、小朋友，还有各位在代码世界里挥洒汗水、在王者峡谷里披荆斩棘的“键盘运动员”们，大家好！我是你们的老朋友——羽教编辑。

回首过去，历经整整7节课的艰苦集训，我们的“王者荣耀AI导师”终于完成了所有基础动作的练习。这就像我们培养一个羽毛球好苗子：

第一章：部署的奥秘——从“本地小卖部”到“全球连锁店” ​

在编程的魔法世界里，把写好的代码放到真实环境中去运行，让它能真正服务于人，这个激动人心的动作，叫做部署（Deployment）。

为了让哪怕是正在上小学三年级的你也能听懂，我们来打个比方： 你经过几年的学习，终于掌握了制作绝世无敌美味“老干妈炒饭”的秘方（写好了代码）。但现在，秘方只存在你的脑子里或者你家的厨房里。你要怎么让别人也吃到呢？

你有两条路可以选：

1. 本地部署（Local Deployment，基于 stdio）：开一家“专属本地小卖部” ​

在计算机里，有一种非常古老且极其高效的通信方式，叫做 stdio（Standard Input/Output，标准输入输出）。

听起来很高大上？其实它就像是你上课时，偷偷给同桌传小纸条。 不需要经过邮局（不需要网络连接），不需要贴邮票（不需要复杂的协议），你直接把写着“今晚开黑？”的纸条塞到同桌手里（进程间直接通信）。

  • 优点：速度快到飞起！因为数据根本不需要经过网线跑到外面去绕一圈，全在你电脑内部的内存里瞬间交换。而且绝对安全，就像你和同桌用衣服挡着传纸条，老师（黑客）根本截胡不到！不需要租服务器，零成本。
  • 缺点：别人想吃你的炒饭？没门！除非他买张机票，飞到你家里，坐在你家的电脑前。也就是说，这个 AI 导师只能在你自己的电脑上运行。

2. 云端部署（Cloud Deployment，基于 SSE/HTTP）：开一家“全球连锁大超市” ​

如果你想让全班同学、全校同学甚至远在外国的网友，都能随时随地请教你的“王者AI导师”，你就必须走出家门，把你的服务挂到互联网上。这就需要用到 HTTP 或者 SSE 技术。

这就好比你注册了一个商标，租了一个云端服务器，开了一家全球连锁的 24 小时外卖店。任何人只要知道你的网址（门店地址），就能下单一碗炒饭。

第二章：网络通信扫盲班——为什么 AI 偏爱“收音机”（SSE）？ ​

如果我们决定开全球连锁店，我们就得选择一种物流配送方式（通信协议）。在讲解代码之前，羽教编辑得先给你们科普三个重要的网络概念。这可是能在同学面前装大神的硬核知识哦！

方式A：传统 HTTP（写信模式） ​

HTTP 就像是你给笔友写信。你写了一封信：“教练，李白怎么出装？”（发送 Request 请求），贴上邮票，扔进邮筒。然后你什么都做不了，只能苦苦等待。服务器那边收到了，查资料，写好回信，再寄给你（返回 Response 响应）。 这是一种“一问一答，问完就跑”的模式。效率太低了！

方式B：WebSocket（打电话模式） ​

WebSocket 就像是你给教练打电话。电话一旦接通，你和教练就可以随时随地同时讲话（双向全双工通信）。你随时可以喊“救命”，教练也可以随时吼你“撤退”。 听起来很完美？但是打电话很贵啊！维持大量的电话线路（长连接）对服务器的压力非常大，就像你同时和一万个人打电话，你的大脑会爆炸的。

方式C：SSE（收音机广播模式）—— AI 的天作之合！ ​

SSE 全称叫 Server-Sent Events（服务器推送事件）。它就像是你打开了收音机，或者订阅了刘畊宏的健身直播间。 你只需要在一开始发送一次请求：“教练，我要进入直播间！”（建立单向连接）。一旦连上，你就不需要再说话了，服务器（教练）会源源不断地把最新的画面、最新的口令推送到你的屏幕上。

为什么大语言模型（LLM）天生绝配 SSE 呢？ 你有没有注意到，像 ChatGPT 或者 Claude 这样的人工智能，它们回答问题的时候，字是一个一个往外蹦的？这在技术上叫 流式输出（Streaming）。AI 的大脑就像是在嗑瓜子，嗑出一颗吐一颗（生成一个 Token 输出一个 Token）。

如果用 HTTP 写信，AI 必须等整整一篇文章全部写完，才能一次性寄给你，你看着屏幕转圈圈，可能会急得砸键盘。 而用了 SSE，AI 每蹦出一个字，就顺着“直播信号”瞬间推送到你的屏幕上，你看到的就是打字机一样的丝滑效果！所以，MCP（Model Context Protocol）协议在云端部署时，官方强烈推荐使用 SSE！

但是！电脑的运行环境（Node.js）其实是不认识 TypeScript 的，它只认识 JavaScript。JavaScript 就像是赛场上自由奔放的比赛服。所以，在上赛场之前，我们必须进行一次“翻译”。

在你的代码编辑器终端（那个黑框框）里，深吸一口气，敲入这句咒语：

第二步：让 AI 认主（配置 JSON 文件） ​

我们要怎么把这个自己写的导师，塞进大名鼎鼎的 Claude 里呢？其实超级简单，不需要你会黑客技术，只需要修改一个“配置表”。

JSON 文件，其实就是程序员世界里的“填空题表格”。Claude 每次启动时，都会去偷偷看一眼这个表格，看看有没有主人给它安排的新任务。

根据你使用的电脑系统，找到这个神秘的表格文件：

  • 如果你用的是 Mac（苹果）电脑，请打开访达（Finder），按下 Cmd + Shift + G，输入：~/Library/Application Support/Claude/claude_desktop_config.json
  • 如果你用的是 Windows 电脑，请按下 Win + R，输入：%APPDATA%\Claude\claude_desktop_config.json

用任何文本编辑器（比如记事本或者 VS Code）打开它。如果里面是空的或者没有这个文件，就自己建一个。然后在里面工工整整地填入以下内容：

第四章：云端进阶实战——用 Express.js 开启全球连锁店 ​

对于好学的同学来说，本地自己玩肯定不过瘾。如果我想把我做的这个牛逼轰轰的 AI 导师发给我的好基友用，但他电脑上根本没装 Node.js 怎么办？

这时候，我们就需要用到大招：云端部署（SSE 模式）。我们要用 Express.js 这个超级大管家，把我们的 AI 服务包装成一个可以通过网址访问的“连锁店”。

首先，我们需要在终端里安装几样装修饭店必备的材料：

bash
npm install express cors
npm install @types/express @types/cors --save-dev
1
2
  • Express：是 Node.js 世界里最著名的网站大管家，负责接待客人、安排包间。
  • CORS：全称跨域资源共享。就像是饭店门口的保安。默认情况下，浏览器不允许别人随便访问你的服务器，CORS 就是保安手里的“通行证”，允许其他网址的客人进来点菜。

接下来，我们在项目里新建一个文件，比如叫 sse-server.ts，然后注入以下魔法代码。大家不用怕，羽教编辑给每一行代码都写了比散文还优美的注释，保证你像看小说一样看懂代码：

typescript
// 导入我们刚才请来的大管家 Express 和保安 CORS
import express from 'express';
import cors from 'cors';
// 导入 MCP 官方提供的 SSE 传输通道（大喇叭）
import { SSEServerTransport } from '@modelcontextprotocol/sdk/server/sse.js';
// 导入我们在前7节课辛辛苦苦写好的、包含所有智慧的 AI 导师实例
import { mentorServer } from './index.js'; 

// 创建一家新的连锁店（Express 应用实例）
const app = express();

// 门口保安放行，允许全球各地的客户端跨域来访问我们
app.use(cors());

// 我们需要一个全局变量，用来存放我们的大喇叭（传输通道）
// 这样不同的客人来的时候，都能听到广播
let transport: SSEServerTransport;

// ---------------------------------------------------------
// 核心路由 1：建立 SSE 连接（学员扫码进入直播间）
// ---------------------------------------------------------
app.get('/sse', async (req, res) => {
  console.log('🔗 叮咚！有新学员进入直播间！准备发放专属接收器...');
  
  // 创建一个 SSE 传输通道。
  // 注意这里的 '/messages'，它告诉客户端：
  // "如果你有问题想问教练，请把纸条塞到 /messages 这个意见箱里！"
  transport = new SSEServerTransport('/messages', res);
  
  // 最激动人心的一步：把我们聪明绝顶的王者导师，强行塞到这个传输通道里！
  // 就像是把教练推到了麦克风前面
  await mentorServer.connect(transport);
  
  console.log('✅ 王者导师已就位，麦克风测试：喂喂喂，能听到吗？');
});

// ---------------------------------------------------------
// 核心路由 2：接收客户端消息（学员在弹幕区提问）
// ---------------------------------------------------------
app.post('/messages', async (req, res) => {
  console.log('📩 收到学员偷偷递上来的提问纸条！');
  
  // 检查一下，如果直播间的大喇叭还没打开，就不能提问
  if (!transport) {
    res.status(400).send('教练还没上线，请先通过 /sse 连接进入直播间！');
    return;
  }
  
  // 把学员的提问纸条（req）交给大喇叭（transport）处理。
  // 教练收到纸条后，经过疯狂的大脑计算，会自动把答案顺着刚才建立好的 SSE 信号广播回去！
  await transport.handlePostMessage(req, res);
});

// ---------------------------------------------------------
// 开门营业！
// ---------------------------------------------------------
const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`\n==============================================`);
  console.log(`🚀 王者荣耀 AI 导师（云端旗舰店）正式盛大开业！`);
  console.log(`📍 门店主页：http://localhost:${PORT}`);
  console.log(`👉 客户端请连接：http://localhost:${PORT}/sse`);
  console.log(`==============================================\n`);
});

考验1：人形电子词典（测试 Resources 能力） ​

你问：“教练，我玩物理刺客，想出件装备，你觉得‘暗影战斧’这件装备怎么样？能加多少攻击？”

发生了什么？ 当你按下回车的一瞬间，Claude 的大脑开始高速运转。它分析了你的话，发现自己不知道“暗影战斧”的具体数值。于是，它毫不犹豫地调用了我们教给它的 Resources（资源库）。 你会在屏幕上看到一行灰色的小字一闪而过：Accessing resource: equipment://暗影战斧...。这是它在偷偷翻开我们写好的 equipments.json 字典。

AI的回答：“这都不懂？你要玩刺客连这件神器都不知道？暗影战斧不仅加 85点物理攻击，还能提供 15%的冷却缩减 和 500点最大生命！最关键的是它的被动‘切割’能增加护甲穿透，被动‘残废’还能减速敌人。这是物理刺客切后排的必备神器，赶紧给我背下来！”

羽教编辑点评：完美！不仅读出了死板的数据，还结合了自己“暴躁教练”的人设进行了生动的讲解！

立刻，马上，给我买【魔女斗篷】！ 扛住第一波法术爆发。然后再补一件【不祥征兆】防兰陵王。作为一个射手，活着才有输出，死了你就是提款机！听懂了没有？！”

羽教编辑点评：太震撼了！AI 准确地通过 Tool 提取了敌方的伤害类型，并根据逆风局势，给出了极其硬核、毫无破绽且极具情绪价值的战术指导！这不比你花钱请的陪玩强一万倍？

考验3：上帝视角的灵魂拷问（测试 Prompts + Tools 组合拳） ​

你问：“教练，现在游戏时间刚刚到 1分40秒，我在对抗路单杀对面一次，现在我正压着对面的塔打，感觉自己天下无敌了！”

发生了什么？ Claude 结合了我们写在 Prompt 里的时间线常识，触发了肌肉记忆。

AI的回答（恨铁不成钢的咆哮）： “压你个头啊压！天下无敌？我看你是去送外卖的！ 用你的脑子想一想，现在是 1分40秒！王者峡谷里的常识是什么？打野在 1分30秒左右刷完一圈野怪，必定到达4级！ 你现在在对抗路压线，你就是对面打野眼里最肥的一块肉！他现在100%正蹲在旁边的草丛里看着你流口水！ 现在，马上，立刻，给我交闪现滚回你自己的防御塔下！ 别送出一血让全队崩盘！”

羽教编辑点评：绝杀！这已经不是一个简单的程序了，它拥有了游戏的大局观和时间嗅觉。这就是 MCP 赋予大语言模型的灵魂！

第六章：赛后复盘与常见除虫指南（FAQ）——教练，我抽筋了！ ​

在真实部署的过程中，你一定会遇到各种报错，这就叫“代码抽筋”。别怕，这就像小队员练球时动作变形一样正常，羽教编辑给你准备了急救包：

  1. 报错：“Connection Refused（连接被拒绝）”

    • 人话翻译：你去饭店吃饭，发现大门紧闭。
    • 原因：你的云端服务器（Express应用）没有运行，或者端口号（比如 3000）被别的程序占用了。
    • 药方：检查终端里是不是忘了敲 node sse-server.js，或者换个端口比如 3001 试试。

  2. 报错：“Command not found（找不到命令）”

    • 人话翻译：裁判找不到你指定的教练。
    • 原因：在本地部署的 JSON 配置文件里，你写的路径不对。或者你的电脑环境变量里没有 node。
    • 药方：仔仔细细检查 claude_desktop_config.json 里的路径，绝对不能有拼写错误。Windows 用户注意路径里的斜杠最好用双反斜杠 \\ 或者正斜杠 /。

  3. 现象：Claude 不调用工具，直接瞎编答案（幻觉）

    • 人话翻译：教练不看战术板，开始满嘴跑火车。
    • 原因：大模型的通病。你问的问题不够明确，或者工具的 description（描述）写得太烂，AI 没意识到应该用工具。
    • 药方：回去修改代码里 Tool 的描述，写得越像大白话越好，明确告诉 AI “当用户询问阵容时，必须调用此工具！”
