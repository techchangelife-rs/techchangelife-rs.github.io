小学生也能懂的AI魔法！王者荣耀AI导师是怎样炼成的？（五）——装上最强大脑：阵容分析与出装推荐 ​

各位未来的AI魔法师、峡谷最强王者们，欢迎回到我们的“AI导师养成计划”！

在上一节课中，我们通过 MCP 的 Resources（资源） 功能，给我们的 AI 导师塞进了一整本《王者图鉴》。现在的它，已经是个能把所有英雄技能倒背如流的“书呆子”了。你问它李白的被动是什么，它能一字不落地背给你听。

但是，打游戏不是背课文啊！

真正的王者峡谷，局势瞬息万变。 如果你问 AI：“教练，对面一楼秒抢了马超，二楼拿了阿古朵，我们这边只有三个脆皮，我该怎么办？” 这时候，如果 AI 只是翻开《王者图鉴》照本宣科地念马超的技能，你肯定恨不得顺着网线过去打它。我们要的不是复读机，我们要的是能帮我们算账、分析、出谋划策的战术大师！

今天，我们就要给这个“书呆子”装上一个“最强大脑”——也就是我们要学习的 MCP 宇宙中最核心、最炸裂的魔法：Tools（工具/技能）。

准备好你的魔法棒（键盘）了吗？我们要开始写代码了！

1. 灵魂拷问：Tools（工具）到底是个啥？它和 Resources（资源）有啥区别？ ​

在正式写代码之前，我们必须先搞懂一个核心哲学问题：静态阅读（Static Reading） 与 动作执行（Action Execution） 的区别。这不仅是 MCP 的核心，也是整个 AI 应用开发（Agent 开发）的灵魂。

1.1 Resources：安静的图书馆（静态阅读） ​

想象一下，Resources 就像是一个巨大的图书馆，或者一份写好的餐厅菜单。AI 是一个超级爱学习的学生。 当 AI 遇到不懂的问题时，它会跑到图书馆，找到你给它准备的《王者图鉴》（Resource），翻开书，把里面的文字从头到尾读一遍（这就是“静态阅读”）。 特点： 只能看，不能改，不能算。资料是死的，写了什么就是什么。它不会因为你今天心情不好，就把书里的字变个颜色。

1.2 Tools：全自动多功能厨房（动作执行） ​

而 Tools 呢？它就像是一个全自动多功能厨房，里面有榨汁机、烤箱、超级计算机，甚至还有一个帮你跑腿的机器人。 当 AI 发现自己算不明白“对面5个法师，我到底该怎么出装才能扛住伤害”时，它不再去翻书了。它会把这个问题写在一张小纸条上，递给你的代码（Tool）。 你的代码接过来一看，立马在后台开始疯狂计算（这就是“动作执行”）： “滴滴滴...检测到敌方 5 名法师...魔法伤害占比 100%...触发保命机制...计算最优解：魔女斗篷 + 不死鸟之眼...” 算完之后，你的代码把结果写在另一张纸条上，递回给 AI。AI 拿到结果，就能自信满满地对你说：“听我的，赶紧出魔女！”

总结一下：

  • Resources 是给 AI 提供静态信息的（比如游戏规则、英雄背景故事）。
  • Tools 是赋予 AI 行动能力和计算能力的（比如进行复杂的数学精算、查询实时天气、甚至帮你点击鼠标自动买装备）。

这就像你给 AI 发了一个“高级算盘”或者“科学计算器”。有了 Tools，AI 就不再只是个会说话的词典，而是一个能真正帮你解决复杂战术问题的数字特工！

（图：把敌我双方的英雄名单扔给Tool，它就能自动算出谁克谁，这就是动作执行的无敌魅力）

2. 门口的墨镜保安：Zod 与 zod-to-json-schema ​

既然 Tools 这么厉害，我们是不是直接把计算器丢给 AI 就行了？ 大错特错！

你得知道，大语言模型（LLM）有时候像个调皮的熊孩子，或者说，它是个“幻觉大师”。它非常容易不按套路出牌。 你让它给你传两个英雄的名字来分析，它可能会给你传一句：“今天天气真不错，我想吃炸鸡”。 你让它传对方的经济差（应该是个具体的数字比如 3000），它可能会给你传个字符串："对面很有钱"。 如果你直接把这些乱七八糟的、不可预测的数据丢进你的核心代码里，你的程序当场就会“原地爆炸”（Crash），屏幕上弹出一堆红色的报错，游戏结束。

为了保护我们的代码不被 AI 的胡言乱语搞崩溃，我们需要在 Tools 的大门入口处，请一位极其严厉、戴着黑墨镜、肌肉发达的顶级保安。 在现代 TypeScript 魔法世界里，这位最强保安的名字就叫 Zod。

2.1 为什么不用原生的 JSON Schema？ ​

在 MCP 的官方协议里，AI 和 Tools 之间是通过一种叫 JSON Schema 的语言来沟通“大招说明书”的。 原生的 JSON Schema 长得非常丑陋，像是一篇繁琐的、上个世纪的八股文。比如你要定义一个包含英雄名字的简单对象，用原生 JSON Schema 写大概是这样的：

json
{
  "type": "object",
  "properties": {
    "heroName": {
      "type": "string",
      "description": "你要查询的英雄名字"
    }
  },
  "required": ["heroName"]
}

2.2 救星登场：Zod + zod-to-json-schema ​

这时候，Zod 闪亮登场。Zod 是一种以 TypeScript 为优先的模式声明和验证库。 用 Zod 写同样的规则，只需要一行半，优雅得像是在写诗：

typescript
const HeroSchema = z.object({
  heroName: z.string().describe("你要查询的英雄名字")
});

然后，我们只需要用一个叫 zod-to-json-schema 的神奇翻译官，就能把 Zod 这种极其优雅的代码，一键翻译成 AI 能看懂的、丑陋的 JSON Schema 八股文。既方便了人类开发者，又满足了 AI 的需求。

Zod 保安的两大核心神技：

  1. 生成说明书（给AI看）： 告诉 AI，你需要给我传什么格式的数据（比如这个必须是字符串，那个必须是正整数）。
  2. 门口搜身（给代码用）： 当 AI 真的把数据传过来准备进入计算器时，Zod 会在门口进行极其严格的“搜身”（通过 .parse() 方法）。如果发现 AI 传的格式不对（比如把数字传成了文字），Zod 会直接一脚把数据踢回去，并且抛出一个大声的警告，告诉 AI：“你传的什么破玩意儿，给我重新传！” 这样就完美保护了我们脆弱的核心业务逻辑不受污染。

3. 打造第一个神级大招：最强BP阵容分析仪 (analyze_lineup) ​

理论知识讲完了，咱们来点真格的。 在王者荣耀里，BP（Ban/Pick，禁用和挑选英雄）环节被称为“神仙打架的第一步”。一个好的阵容，往往能让比赛赢在起跑线上。很多时候，输赢在选完人的那一刻就已经注定了。

我们要在 src/tools/lineup.ts 里，写一个极其聪明的阵容分析器。我们要让它不仅能识别英雄，还能看懂阵容的物理/魔法伤害比例，检查有没有控制技能，甚至能处理小学生玩家故意打错英雄名字的“边缘情况（Edge Cases）”。

3.1 请保安写说明书（定义 Schema） ​

首先，我们把 Zod 保安请出来，定下规矩：

typescript
// src/tools/lineup.ts
import { z } from "zod";
import { zodToJsonSchema } from "zod-to-json-schema";

// 告诉AI：你必须给我传这两个名单，而且必须是字符串数组！少一个都不行！
export const AnalyzeLineupSchema = z.object({
  myTeam: z.array(z.string()).describe("咱们这边的英雄名单，例如 ['亚瑟', '后羿']"),
  enemyTeam: z.array(z.string()).describe("对面那帮人的英雄名单，例如 ['兰陵王', '安琪拉']"),
});

// 包装成 MCP 认识的“大招说明书”
export const analyzeLineupToolDef = {
  name: "analyze_bp_lineup",
  description: "在选人阶段（BP）深度分析阵容优劣，判断物理/魔法伤害比例、控制能力，并给出战术和最后选人的建议。",
  inputSchema: zodToJsonSchema(AnalyzeLineupSchema),
};

3.2 建立核心数据库与“黑话字典” ​

玩家在游戏里可不会总是乖乖输入官方名字。他们会用语音输入说“猴子”、“卤蛋”、“老亚瑟”。作为最强 AI 导师，如果连这些黑话都听不懂，那就太掉价了。这就叫处理边缘情况（Edge Cases）。

同时，我们需要一个内置的英雄属性小金库，用来精算伤害类型和英雄定位。

typescript

  // ... 实际开发中这里会填满100多个英雄的详细数据

// 翻译外号的超级净水器函数
function normalizeHeroName(name: string): string {
  const cleanName = name.trim();
  return HERO_ALIASES[cleanName] || cleanName;

3.3 编写最强大脑：核心算账与推演逻辑 ​

接下来，就是见证奇迹的时刻。我们要写一个极其复杂的分析函数。这段代码会让 AI 看上去像是一个有着十年执教经验、拿着战术板的 KPL 冠军教练。

typescript
export async function executeAnalyzeLineup(args: any) {
  // 【生死攸关的一步】让 Zod 保安检查参数，如果 AI 乱传数据，这里直接报错拦截！
  const parsed = AnalyzeLineupSchema.parse(args);
  
  // 翻译黑话，把“吉吉国王”统统净化成“孙悟空”
  const myTeam = parsed.myTeam.map(normalizeHeroName);
  const enemyTeam = parsed.enemyTeam.map(normalizeHeroName);

  let adviceList: string[] = [];
  let tactics = "正常发育，稳扎稳打。";

  // ================= 1. 阵容完整性深度扫描 =================
  if (myTeam.length > 0 && myTeam.length < 5) {
    let hasTank = false;
    let hasMage = false;
    
    myTeam.forEach(hero => {
      const stats = HERO_DATABASE[hero];
      if (stats) {
        if (stats.role === "TANK" || stats.role === "SUPPORT") hasTank = true;
        if (stats.role === "MAGE") hasMage = true;
      }
    });

    if (!hasTank) {
      adviceList.push("🚨 严重警告：咱们这套阵容没前排啊兄弟们！团战一碰就碎，最后几楼赶紧补个【张飞】或者【廉颇】顶在前面挨揍！");
    }
    if (!hasMage) {
      adviceList.push("⚠️ 阵容提示：缺少法术输出！对面全员出个不祥征兆咱们就打不动了，中单赶紧拿个法师！");
    }
  }

  // ================= 2. 奇葩阵容防爆检测 (Edge Cases) =================
  let adcCount = 0;
  myTeam.forEach(hero => {
    if (HERO_DATABASE[hero]?.role === "ADC") adcCount++;
  });
  if (adcCount >= 3) {
    adviceList.push("🤬 教练血压已经高了！你们在玩大乱斗吗？！选 3 个射手是想在泉水里凑一桌麻将吗？趁还没开局赶紧重开！");
  }

  // ================= 3. 敌方伤害比例精算与针对性克制 =================
  let enemyMagCount = 0;
  let enemyPhyCount = 0;
  let enemyHasInvisible = false;

  enemyTeam.forEach(hero => {
    const stats = HERO_DATABASE[hero];
    if (stats) {
      if (stats.damageType === "MAG") enemyMagCount++;
      if (stats.damageType === "PHY") enemyPhyCount++;
    }
    // 检测恶心人的老六英雄
    if (hero === "兰陵王" || hero === "阿轲" || hero === "鬼谷子") {
      enemyHasInvisible = true;
    }
  });

  // 如果对面一堆法师（比如露娜打野、不知火舞中单、司空震对抗路，俗称法师队）
  if (enemyMagCount >= 3) {
    tactics = "🛡️ 敌方法术伤害占比极高！提醒全员：第二件装备必须安排上【抵抗之靴】或【魔女斗篷】，对面就是一群脆皮法术炮台，扛过第一波爆发就能反杀！";
  } else if (enemyPhyCount >= 4) {
    tactics = "🧱 敌方几乎全是物理输出，也就是俗称的‘菜刀队’。咱们这边的坦克只要闭着眼睛出【极寒风暴】和【反伤刺甲】，对面打你就像是在刮痧。";
  }

  // 查查对面有没有隐身老六
  if (enemyHasInvisible) {
    tactics += "\n👁️ 红色警报！对面有隐身老六（兰陵王/阿轲），辅助出门什么都别管，立刻马上买个辅助装【形昭之鉴】！别让你们家可怜的射手连怎么死的都不知道。";
  }

  // 返回给 AI 的高维结构化报告
  return {
    matchupSummary: `我方阵容(${myTeam.length}人): ${myTeam.join(", ")} VS 敌方阵容(${enemyTeam.length}人): ${enemyTeam.join(", ")}`,
    coreAdvice: adviceList.length > 0 ? adviceList.join("\n") : "阵容非常扎实，有肉有输出，控制链完美，这把只要不送包赢！",
    tacticalDeployment: tactics
  };
}

4. 打造第二个神级大招：动态保命出装推荐 (recommend_build) ​

出装，是王者荣耀里最考验智商和应变能力的环节。 很多新手玩家最大的毛病就是“死脑筋”——不管顺风逆风，不管对面是谁，永远按着系统推荐的出装顺序一件一件买。 对面三个法师，他还搁那憋加物理防御的“不祥征兆”；明明自己这边已经被打得高地都没了，经济落后五千块，他还在攒大几千块钱买“破军”。

我们要写第二个 Tool，让 AI 能够根据当前局势的经济差和敌方的具体威胁，动态计算出最科学的装备搭配。拒绝死板，活着才有输出！

（图：根据顺逆风和敌方核心威胁，智能推荐出装路线，真正的对症下药！）

4.1 请保安写说明书 ​

在 src/tools/build.ts 里，我们再次呼叫 Zod 保安，这次的说明书更精细了：

typescript
// src/tools/build.ts
import { z } from "zod";
import { zodToJsonSchema } from "zod-to-json-schema";

export const RecommendBuildSchema = z.object({
  heroName: z.string().describe("你要查询出装的英雄名字"),
  goldDiff: z.number().describe("目前的经济差。正数代表领先，负数代表落后（逆风）"),
  enemyThreat: z.enum(["NONE", "HEAVY_CC", "BURST_MAGIC", "HIGH_PHYSICAL"]).describe("对面当前最大的威胁是什么？枚举值：NONE(没有) / HEAVY_CC(重度控制) / BURST_MAGIC(高爆发法术) / HIGH_PHYSICAL(高物理伤害)"),
});

export const recommendBuildToolDef = {
  name: "recommend_build",
  description: "根据当前局势（经济差、敌方最大威胁），动态推荐最抗揍或最暴力的出装路线。绝不教条！",
  inputSchema: zodToJsonSchema(RecommendBuildSchema),
};

4.2 编写动态出装核心逻辑 ​

这里的逻辑，我们将展现什么叫真正的“因地制宜，看人下菜碟”：

typescript
export async function executeRecommendBuild(args: any) {
  // Zod 搜身验证，绝对不允许乱七八糟的数据混进来
  const parsed = RecommendBuildSchema.parse(args);
  const { heroName, goldDiff, enemyThreat } = parsed;
  
  // 基础模板：假设玩家玩的是射手（这里为了简化，我们以通用物理输出为例）
  let boots = "急速战靴"; // 俗称攻速鞋
  let coreItems = ["无尽战刃", "破晓"];
  let defenseItem = "名刀·司命";
  let reason = "标准输出流，按部就班正常发育即可。";

  // ====== 1. 应对敌方特殊威胁 (生存法则) ======
  if (enemyThreat === "HEAVY_CC") {
    boots = "抵抗之靴"; // 对面控制多，必须换抵抗鞋减免控制时间
    reason = "对面控制技能太多了（什么冰冻、击飞、眩晕），穿攻速鞋进场就是罚站，必须换【抵抗之靴】免控！少点攻速总比死了强。";
  } else if (enemyThreat === "BURST_MAGIC") {
    defenseItem = "魔女斗篷";
    reason = "对面法师发育太好，爆发太高，不出【魔女斗篷】你会被瞬间融化！活着才有输出，不要贪那点攻击力！";
  } else if (enemyThreat === "HIGH_PHYSICAL") {
    defenseItem = "不祥征兆";
    reason = "对面物理刺客或者猴子盯上你了，补个【不祥征兆】减他们攻速，教他们做人，让他们敲不动你。";
  }

  // ====== 2. 顺逆风局势判断 (经济学原理) ======
  if (goldDiff <= -3000) {
    // 逆风局（落后 3000 块以上，穷得叮当响）
    coreItems = ["暗影战斧", "碎星锤"]; // 逆风憋不出昂贵的破晓，换便宜且成型快的碎星锤
    defenseItem = "反伤刺甲"; // 逆风必须出肉保底
    reason = `兄弟，咱们现在落后 ${Math.abs(goldDiff)} 块钱，纯纯的逆风局，快吃不起饭了！千万别想着憋【破晓】这种大件了，赶紧把性价比极高的【碎星锤】和【反伤刺甲】掏出来，守住高地，苟住就是胜利！\n结合威胁分析：` + reason;
  } else if (goldDiff >= 4000) {
    // 顺风局（领先 4000 块以上，富得流油）
    coreItems = ["无尽战刃", "破晓", "破军"]; // 顺风局直接拉满极致伤害
    defenseItem = "贤者的庇护"; // 复活甲，增加容错率
    reason = `咱们现在领先 ${goldDiff} 块钱，大顺风，富可敌国！别给对面任何喘息的机会，直接掏出最贵的【破军】和【复活甲】，越塔强杀，一波推平他们水晶！`;
  }

  const finalBuild = [boots, ...coreItems, defenseItem];

  // 返回装配好的终极指南给 AI
  return {
    targetHero: heroName,
    situation: goldDiff < 0 ? "逆风防守阶段" : "顺风压制阶段",
    recommendedBuild: finalBuild,
    coachReasoning: reason
  };
}

5.1 数据流是怎么跑通的？(高阶原理解析) ​

为了让你彻底弄懂，我们用一个送快递的例子来拆解完整的请求流程：

  1. 玩家发问：你说“对面五个法师，我玩鲁班该出什么？”
  2. AI 思考：AI 发现《王者图鉴》（Resource）里没有现成答案，于是它决定看一眼墙上的工具菜单（ListToolsRequestSchema）。
  3. 点菜下单：AI 发现 recommend_build 这个工具刚好能解决问题。于是 AI 按照 Zod 写的说明书，把 heroName="鲁班七号" 和 enemyThreat="BURST_MAGIC" 打包成一个 JSON 快递包裹，发给 MCP（CallToolRequestSchema）。
  4. 保安拦截：包裹送到门口，Zod 保安拆开检查，发现格式完全正确，放行！
  5. 核心计算：代码疯狂运转，得出了“必须出魔女斗篷”的结论，并打包成新的结果包裹返回。
  6. AI 润色：AI 收到结果包裹，把它翻译成人类听得懂的、充满感情的语音播报讲给你听。

明白了吗？这就是神级 AI 的完整思考闭环！

5.2 编写挂载代码 ​

下面是具体的实现代码：

typescript
// src/index.ts
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { ListToolsRequestSchema, CallToolRequestSchema } from "@modelcontextprotocol/sdk/types.js";

// 导入我们刚刚写的两个大招和它们的专属说明书
import { analyzeLineupToolDef, executeAnalyzeLineup } from "./tools/lineup.js";
import { recommendBuildToolDef, executeRecommendBuild } from "./tools/build.js";

const server = new Server({ name: "hok-ai-coach", version: "1.0.0" }, { capabilities: { tools: {} } });

// ================= 第一步：把大招的名字挂到墙上（向 AI 展示菜单） =================
server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      analyzeLineupToolDef,  // 阵容分析仪
      recommendBuildToolDef  // 动态出装推荐
    ],
  };
});

// ================= 第二步：当 AI 喊出大招名字时，我们帮它放技能 =================
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name, arguments: args } = request.params;

  try {
    let result;
    
    // 路由分发：根据 AI 喊出的名字，调用后台对应的核心计算逻辑
    if (name === "analyze_bp_lineup") {
      result = await executeAnalyzeLineup(args);
    } else if (name === "recommend_build") {
      result = await executeRecommendBuild(args);
    } else {
      // 防御性编程：万一 AI 突然发神经，喊了一个根本不存在的名字
      throw new Error(`不好意思，本教练没学过这个大招啊，别瞎喊: ${name}`);
    }

    // 执行成功，把算好的结果写在纸条上，以 JSON 文本的格式原路传回给 AI
    return {
      content: [{ type: "text", text: JSON.stringify(result, null, 2) }],
    };
    
  } catch (error: any) {
    // 【终极绝招】：如果 Zod 报错（比如 AI 传了错误类型的数据），我们会在这里抓住错误
    // 并且把错误信息原样返回给 AI。聪明的 AI 看到错误信息后，会自动修正参数重新调用！
    return {
      content: [{ type: "text", text: `工具调用报错啦！请检查你的参数输入格式: ${error.message}` }],
      isError: true, // 告诉 AI 这是一个失败的结果，需要它自我反思
    };
  }
});
