小学生也能懂的AI魔法！王者荣耀AI导师是怎样炼成的？（四）——给AI喂饭式教学：构建知识库彻底消灭“胡说八道” ​

亲爱的大朋友、小朋友们，欢迎回到我们的“王者荣耀AI导师”魔法课堂！

在前面的三节课里，我们已经像搭积木一样，成功地把“王者导师”的接待大厅（MCP Server）给搭建起来了。这就好比我们开了一家王者荣耀咨询诊所，甚至还请来了一位智商高达两百的超级AI大模型来坐诊。

但是，昨天发生了一件让人哭笑不得的事情。 我兴冲冲地跑去问这个刚刚连上线的AI导师：“导师导师，这赛季马超怎么出装才能带飞全场？” 结果，这位顶着高智商光环的AI导师，竟然一本正经、摇头晃脑地对我说：“我建议你第一件装备先出个‘冰霜长矛’，然后再补一个‘打野刀’，这样就能在线上无敌了！”

听到这个回答，我差点一口老血喷在屏幕上。 冰霜长矛？！ 这件装备在王者荣耀里早就被天美策划给删掉几百年了好吗！现在的马超连鞋子都不用出，你让我出冰霜长矛？这要是让我在排位赛里这么玩，我的四个队友估计会顺着网线过来把我给“物理超度”了。

原来，现在的AI大模型虽然聪明，但它就像个**“云玩家”**。它的脑子里装满了全世界的知识，但唯独没有王者荣耀最新版本的补丁说明。

为了不让我们的AI导师变成坑队友的罪魁祸首，今天这一课，我们要开启一项伟大的工程——对AI进行“喂饭式教学”！ 我们要亲手为它打造一个实时更新的知识库，让它变成真正的最强王者！

第一章：AI为什么会“睁眼说瞎话”？（致命的“幻觉”与拯救者RAG） ​

在给AI“喂饭”之前，我们必须先弄明白一个非常核心、非常前沿的AI心理学问题：为什么AI会胡说八道？

1. 什么是AI的“幻觉”（Hallucination）？ ​

在人工智能领域，有个极其专业的词汇叫作**“幻觉”（Hallucination）。别害怕，这不是说AI吃错了蘑菇看到了小精灵，而是指AI在回答问题时，用极其自信的语气，说出了完全错误、甚至是凭空捏造的事实。**

我们可以用一个“小学生考试”的生动比喻来理解它。 想象一下，班里有个叫“小A”的同学（也就是我们的AI大模型）。小A绝顶聪明，博览群书，但他有一个致命的弱点：他被关在家里，两年没有上过网了。（这就是AI的“知识截止日期” Knowledge Cutoff Date）。

有一天，语文老师突然进行突击考试，考卷上有一道题：“请问2026年王者荣耀KPL春季赛的总冠军是哪支队伍？” 小A懵了，因为他脑子里的记忆只停留在2023年。但是！小A是个极其爱面子、极度渴望讨好老师的“好学生”。他心想：“我不能交白卷啊！交白卷老师会觉得我笨。根据我以前的经验，eStarPro或者狼队挺厉害的，我就随便编一个吧！”

于是，小A在考卷上洋洋洒洒地写下：“2026年的总冠军是eStarPro，他们在决赛中以4:0战胜了对手，尤其是花海的打野发挥了至关重要的作用……”

老师一看，写得有模有样，细节满满，但其实全都是瞎编的！ 这就是AI的“幻觉”。它太想给你一个完整的答案了，以至于当它不知道真相时，它会利用自己的语言天赋，编造一个听起来无比合理的谎言。

2. 游戏领域的灾难：一天一个样的版本更新 ​

在其他领域，幻觉可能只是个小问题（比如你问李白是哪个朝代的，这个知识几千年都不会变）。但在电子竞技和游戏领域，幻觉是灾难性的！

王者荣耀的数据更新有多快？

  • 昨天亚瑟的护盾还很厚，今天就被削弱了。
  • 上个月还能买到的装备，这个月就重做了。
  • 英雄的克制关系、出装思路，甚至地形和草丛的位置，每个赛季都在天翻地覆地变化。

如果你指望AI仅凭它几年前在网上“背诵”的旧知识来指导你打今天的排位赛，那你就是在拿自己的星星开玩笑。

3. 拯救幻觉的超级英雄：RAG（检索增强生成） ​

那么，怎么解决这个问题呢？是不是每次王者荣耀一更新，我们就得花几千万美金，把整个AI大模型重新训练一遍？（这叫微调 Fine-tuning） 当然不是！就算你家里有矿，时间上也来不及啊。

这时候，全村的希望——RAG（Retrieval-Augmented Generation，检索增强生成） 闪亮登场了！ 名字听起来像是在念咒语，但其实它的原理，任何一个上过小学的人都能秒懂：把“闭卷考试”变成“开卷考试”！

既然小A同学不知道最新版本的知识，那我们就不强迫他背诵了。我们直接给他发一本**《最新版王者荣耀官方百科全书》，并告诉他：“小A，以后再有人问你王者荣耀的问题，你先翻书，查到了再回答**，书上没写的你就不许瞎编！”

让我们拆解一下 RAG 的魔法步骤：

  • R (Retrieval / 检索)：当用户提问“马超怎么出装”时，AI先去“百科全书”里寻找“马超”和“装备”的相关页面。
  • A (Augmented / 增强)：AI把找到的页面内容（比如马超的最新属性、推荐装备列表）当作“小抄”，夹在考卷里。
  • G (Generation / 生成)：AI看着这张绝对准确的“小抄”，运用它强大的语言组织能力，给你写出一篇通俗易懂、完美无瑕的攻略。

通过 RAG 技术，我们既保留了 AI 超强的阅读理解和总结能力，又彻底锁死了它的知识源头，完美消灭了“幻觉”！而我们要做的，就是为AI提供这本《百科全书》。

第二章：什么是MCP的Resources（资源）？——你的“魔法书架” ​

既然决定了要让AI开卷考试，那我们就需要一个能存放资料、并且能让AI随时翻阅的地方。这就是 MCP 协议中极其重要的核心模块：Resources（资源）。

你可以把 MCP 的 Resources 模块想象成一个安装在你电脑里的**“魔法书架”**。

在传统的聊天里，AI是摸不到你电脑里的文件的。但有了 MCP 和 Resources，你就相当于在AI和你的电脑硬盘之间建了一座图书馆。你可以把你整理好的任何数据（文本、代码、甚至图片）放在这个书架上，供AI随时取用。

让我们来看一张通俗易懂的工作流图：

（图：这就是喂饭式教学的真谛！AI遇到不懂的问题，再也不敢瞎编了，而是老老实实地先看书，看懂了再回答你。）

Resources 与 Tools（工具）有什么区别？ 在 MCP 的世界里，有 Resources 和 Tools 两个概念，初学者很容易搞混。

  • Resources（资源）是用来“读”的。 它就像图书馆里的藏书。AI只能翻看它，不能修改它。它通常用来提供静态的、大量的背景知识（比如英雄的属性、装备的价格表）。
  • Tools（工具）是用来“做”的。 它就像是瑞士军刀。AI可以通过调用工具来执行某个动作（比如去网上实时抓取某场比赛的比分，或者帮你计算某个技能的伤害值）。

在当前阶段，我们的首要任务是让AI熟悉游戏的基础设定，所以我们先教它如何阅读 Resources。

第三章：准备教材：编写英雄与装备的“武功秘籍” ​

要让AI读书，我们总得先有书吧！现在，请打开你的代码编辑器（VS Code），我们要开始撰写《王者荣耀武功秘籍》了。

我们在项目里的 src 文件夹下，新建一个名为 data 的文件夹。这里就是我们的“魔法书架”的实体所在地。我们将在这里创建两本极其重要的教材，并使用一种叫做 JSON 的语言来编写。

为什么用 JSON？ ​

JSON（JavaScript Object Notation）听起来很高大上，但对AI来说，它就是一种“整理玩具的收纳盒”。 如果我用普通话写一大段文章：“亚瑟是个战士，他很肉，弱点是马可波罗……” AI读起来会比较费劲，因为需要从大段文字里抓取重点。 但是用 JSON，我们就把信息分门别类地装进了有标签的小格子里。AI一眼扫过去，立刻就能精准拿到数据！

在 JSON 里：

  • [ 和 ] 代表一个大箱子（数组），里面可以装很多东西。
  • { 和 } 代表一个具体的小物件（对象），比如一个特定的英雄。
  • "标签名": "内容" 则是给小物件贴上属性标签。

第四章：给魔法书架贴上“专属条形码”——深度揭秘 URI 与自定义协议 ​

书写好了，放在了 src/data 文件夹里。但AI怎么知道这本书在哪呢？难道我们直接告诉它路径 C:\MyProject\src\data\heroes.json 吗？

千万不要！ 在 MCP 的魔法世界里，为了安全和统一管理，我们不允许AI直接去翻你的电脑硬盘。这就像你去图书馆借书，你不能自己冲进仓库乱翻，你必须通过前台的图书管理员，报出书的索书号（条形码）。

在计算机世界里，这个“条形码”叫做 URI（Uniform Resource Identifier，统一资源标识符）。

URL 和 URI 是亲戚吗？ ​

你肯定听过 URL（比如 http://www.baidu.com），也就是网址。URL 是 URI 的一种。 URL 强调的是“这个东西在哪里”（比如在百度服务器上）。 而 URI 更广泛，它只强调“这个东西是什么”。

在我们的项目中，我们要为我们的书籍创造一种**“自定义协议”（Custom Protocol Scheme）**！

如果你经常上网，你会看到网址都是以 http:// 或 https:// 开头的。这叫做 HTTP 协议。 如果你在浏览器里打开本地文件，它可能是 file:/// 开头的。

今天，我们要当一回造物主，创造一个属于我们自己的王者荣耀专属协议：hok:// ！（hok 是 Honor of Kings 的缩写）。

我们将给《英雄图鉴》贴上这样的条形码： hok://knowledge/heroes

我们将给《装备大全》贴上这样的条形码： hok://knowledge/equipments

为什么要这么做？这有什么好处？

  1. 超级酷炫： 这就像是哈利波特的九又四分之三站台！hok:// 就像一个只有我们和AI懂的魔法暗号。
  2. 极度安全： AI 只能请求 hok:// 开头的书，它永远无法请求 file:///C:/Windows/System32/密码本.txt。这保证了你电脑里其他文件的绝对安全。
  3. 抽象解耦： AI 不需要知道这些数据是存在本地的 JSON 文件里，还是存在云端的数据库里。它只需要大喊一声“我要看 hok://knowledge/heroes”，我们的 MCP 服务器就会负责把书找来递给它。

这，就是顶级程序员的设计思维！把复杂的内部实现隐藏起来，只对外暴露一个优雅的条形码。

第五章：代码实战第一步：制作“图书目录”（ListResourcesRequestSchema） ​

理论知识学完了，咱们该撸起袖子写代码了！请打开前台接待处的代码文件 src/index.ts。

我们的目标是完成两件事：

  1. 当 AI 问：“你这里都有什么书？”时，我们要递给它一本图书目录。
  2. 当 AI 说：“我要看条形码为 XXX 的书”时，我们要把书的内容读出来给它听。

首先，我们要引入一些 Node.js 的“小跑腿”工具，用来读取本地文件。

typescript
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
// 引入 Resources 相关的两个重要法则（Schema）
import {
  ListResourcesRequestSchema,
  ReadResourceRequestSchema,
} from "@modelcontextprotocol/sdk/types.js";
import fs from "fs/promises"; // 负责读文件的跑腿小弟（支持异步）
import path from "path";      // 负责拼凑文件路径的向导
import { fileURLToPath } from "url"; // 帮我们找到当前文件所在位置的指南针

// 获取当前代码文件所在的目录路径
const __dirname = path.dirname(fileURLToPath(import.meta.url));

// 编写一个帮你拿书的小跑腿函数
async function loadData(filename: string) {
  // 把目录路径、data文件夹和文件名拼在一起，就像拼乐高一样
  const filePath = path.join(__dirname, "data", filename);
  // 跑腿小弟去硬盘上读取文件内容，"utf-8"代表我们要读的是人类能看懂的字符，不是乱码
  const data = await fs.readFile(filePath, "utf-8");
  // 读出来的是一长串文本，我们要把它变回 JSON 魔法盒子（对象）
  return JSON.parse(data);
}

在 MCP SDK 中，我们使用 server.setRequestHandler 来处理特定类型的请求。ListResourcesRequestSchema 就是专门用来处理“查询资源列表”请求的规则。

typescript

划重点啦，同学们！ 请特别注意代码里的 description（描述）字段。这个字段极其、极其、极其重要！ AI 并不知道 hok://knowledge/heroes 里面具体写了什么。当用户提出一个问题时，AI 是通过阅读这里的 description 来决定**“我到底需不需要去借这本书”**的。

如果你的描述写得含糊其辞，比如“英雄资料”，AI 可能在遇到克制问题时就不会去读它。 但如果你在描述里写明了：“当用户询问如何针对某个英雄时，务必阅读此书！”，AI 就会像听话的乖宝宝一样，立刻通过这个目录找到这本秘籍。这就叫做对 AI 的**“引导式提示”**。

至于 mimeType: "application/json"，它叫做媒体类型（MIME Type）。这就好比告诉 AI：“这本书不是用中文写的普通小说，也不是一张 JPG 图片，它是用 JSON 这种结构化数据格式写的。” 这样 AI 在拿到书后，就会自动戴上“解析 JSON”的专用眼镜去阅读它。

第六章：代码实战第二步：化身“图书管理员”（ReadResourceRequestSchema） ​

目录给出去之后，AI 马上就会拿着条形码来找我们要具体的书了。 这时候，我们要响应第二种请求：读取资源（Read Resource）。

我们继续在 src/index.ts 中添加以下代码：

typescript
// 动作二：AI点名要看哪本书，你就化身管理员翻给它看
server.setRequestHandler(ReadResourceRequestSchema, async (request) => {
  // AI 递过来的条形码就藏在 request.params.uri 里
  const uri = request.params.uri;

  // 检查条形码是不是《英雄图鉴》
  if (uri === "hok://knowledge/heroes") {
    // 召唤我们的跑腿小弟去硬盘上把数据拿过来
    const heroes = await loadData("heroes.json");
    
    // 把书打包好递给 AI
    return {
      contents: [
        { 
          uri: uri, // 告诉 AI，这就是你要的那个条形码对应的书
          mimeType: "application/json", 
          text: JSON.stringify(heroes) // 把 JSON 魔法盒子重新压扁成一长串文本，方便网络传输
        }
      ],
    };
  }

  // 检查条形码是不是《装备大全》
  if (uri === "hok://knowledge/equipments") {
    const equipments = await loadData("equipments.json");
    return {
      contents: [
        { 
          uri: uri, 
          mimeType: "application/json", 
          text: JSON.stringify(equipments) 
        }
      ],
    };
  }

  // 如果 AI 拿着一个乱七八糟的条形码来找我们（比如 hok://knowledge/aliens）
  // 我们就要毫不客气地报错，把它赶出去！
  throw new Error(`没这本书啊老板！找不到对应的资源：${uri}`);
});

这段代码里藏着几个非常巧妙的设计：

  1. async/await 异步魔法： 你看到 async 和 await 了吗？去硬盘里找文件是需要花时间的（虽然对电脑来说只有几毫秒，但也是时间）。如果我们不用 await，程序就会像个急性子，还没等小弟把书拿回来，就急急忙忙地把一个空包裹递给 AI 了。加上 await，就是告诉程序：“你在这儿给我老老实实等着，等小弟把 heroes.json 彻底拿回手里了，再往下执行！” 这保证了我们的服务绝对可靠。

  2. 为什么 contents 是个数组（用 [ 和 ] 包裹）？ 细心的同学可能会问，为什么返回的是 contents: [{...}]，而不是直接返回里面的对象？ 这是因为 MCP 协议设计得非常长远。有时候，一个条形码可能对应着一套丛书（多本书）。所以协议规定，即使你只找到了一本书，也要把它装在一个箱子（数组）里递过去，以保持格式的统一。

  3. JSON.stringify 的扁平化处理： 我们在硬盘里存的是字符串，用 loadData 把它变成了 JavaScript 对象（立体的盒子），为什么返回给 AI 之前又要用 JSON.stringify 把它变回字符串文本呢？ 因为在网络世界的数据传输管道里，只能流淌“扁平的字符串文本”或者“二进制水流”。立体的对象是塞不进网线里的。这就好比你要寄一个组装好的巨型乐高城堡，快递箱塞不下，你只能把它拆成零件，附上一张说明书（MIME Type），让对面的 AI 收到后再自己组装在脑子里。

你问： “对面选了鲁班七号，我正在玩亚瑟，请问我该怎么针对他？第一件装备出什么最好？”

接下来，就是见证 RAG 魔法和 Resources 威力运作的绝妙瞬间！虽然我们在屏幕前只等了几秒钟，但在 AI 的脑海里，发生了一场惊心动魄的“极速查字典比赛”：

  1. 思考需求： AI 看到“鲁班七号”、“亚瑟”、“针对”、“出装”。它心想：“完蛋，我记忆里的王者荣耀还是两年前的，我可不能瞎编。”
  2. 查询目录： AI 偷偷向我们的 MCP 服务器发送了 ListResourcesRequestSchema 请求。
  3. 锁定目标： MCP 服务器返回了目录。AI 一看描述：“哈！《英雄图鉴》里写了能查弱点，《装备大全》里写了能查装备！这两本我都要看！”
  4. 借阅书籍： AI 迅速向 MCP 发送了两次 ReadResourceRequestSchema 请求，条形码分别是 hok://knowledge/heroes 和 hok://knowledge/equipments。
  5. 疯狂阅读： MCP 服务器通过跑腿小弟读取 JSON 文件，转换成文本返回给 AI。AI 一目十行，瞬间提取了关键信息：
    • （阅读英雄篇）：鲁班七号，小短腿，弱点是刺客突脸。亚瑟，一技能有沉默，专治花里胡哨。
    • （阅读装备篇）：暗影战斧，加攻击加冷却加穿透，技能还能减速，亚瑟的绝配！
  6. 融合生成： AI 结合自己原本就拥有的超强逻辑和语言能力，将读到的死板的 JSON 数据，转化成了生动活泼的语言。

“兄弟，对面敢拿鲁班七号，那不是纯纯的提款机吗！ 你选亚瑟简直太对了！根据最新的数据，鲁班七号是个毫无位移的‘小短腿’，最怕的就是你这种能直接突脸的英雄。你亚瑟的一技能带有沉默效果，只要你开启一技能加速冲过去，一刀砍在他头上让他放不出技能，他只能原地罚站挨打。 至于出装，听我的，第一件直接裸一把**【暗影战斧】**！这件装备不仅能给你增加血量和攻击力，更重要的是它能提供破甲效果。配合它的被动‘残废’减速，鲁班一旦被你粘住，插翅也难飞。冲就完事了，德玛西亚……啊不对，为了圣骑士的荣耀！”
