小学生也能懂的AI魔法！王者荣耀AI导师是怎样炼成的？（三）——搭个草台班子准备写代码 ​

各位未来的AI魔法师们，欢迎回来！

在前面的两节课里，我们像是在茶馆里听书，纸上谈兵地聊了聊什么是大语言模型（LLM），什么是MCP（Model Context Protocol）协议。很多同学可能听得热血沸腾，但也可能听得昏昏欲睡，心里直犯嘀咕：“老师，你说的这MCP协议比王者荣耀的星耀局还玄乎，到底长啥样啊？我们什么时候才能真正开始敲键盘写代码啊？”

别急！光说不练假把式！ 从今天这篇教程开始，我们要正式卷起袖子，戴上安全帽，进入施工现场了！我们要亲手在自己的电脑上，一砖一瓦地搭建起一个**“王者荣耀AI导师”的服务站（MCP Server）**。

如果你是个连代码长啥样都没见过的小学生，或者是一个平时只用电脑玩游戏、看视频的纯小白，千万别害怕退缩！请把写代码想象成搭乐高积木或者开一家属于你自己的虚拟餐厅。只要你跟着我的步骤，一步一步来，你会发现，原来创造一个能和AI对话的系统，竟然这么简单、这么好玩！

准备好你的键盘了吗？深呼吸，魔法马上就要开始了！

第一章：开工前的准备——我们需要什么兵器？（极简技术栈大解密） ​

俗话说得好：“工欲善其事，必先利其器。” 就像你要在王者峡谷里大杀四方，必须要先买好暗影战斧和破军一样；我们要在电脑里建起一座AI服务站，也需要准备几样称手的兵器。

不用担心我们会用到什么极其复杂、让人眼花缭乱的工具。为了让大家轻松上手，我为大家挑选了目前业界最流行、但也最容易入门的“极简三件套”。

（图：我们要用到的三样法宝：Node.js、TypeScript、MCP SDK）

让我们来挨个认识一下这三位好帮手，以及为什么我们非要用它们不可。

1. Node.js：代码的“无敌厨房” ​

它是什么？ 如果你听说过 JavaScript（简称 JS），你可能知道它是用来做网页特效的。比如网页上飘落的雪花、点击后会弹出的窗口，都是 JS 写的。但是，JS 以前就像是一个被关在浏览器（比如 Chrome 或 Edge）这个“透明玻璃箱”里的宠物，它只能在网页里活动，出不来。 后来，一位名叫 Ryan Dahl 的大神觉得这太憋屈了，于是他把 JS 从浏览器里解放了出来，给它装上了一个强大的引擎，这就是 Node.js。有了 Node.js，JavaScript 就可以直接在你的电脑系统里运行了，它可以读取你的硬盘文件、连接网络、甚至控制你的电脑！

为什么我们要用它？ 如果把写代码比作做菜，那么 Node.js 就是我们的**“无敌厨房”**。我们的“王者导师”需要读取本地的英雄数据文件，需要时刻准备着接收大模型发来的请求，这就必须要在电脑的后台一直运行着。Node.js 就像是一个不知疲倦的超级厨师长，能够高效地处理各种并发的任务。而且它非常轻量级，安装简单，是目前开发 MCP Server 最主流的选择。

2. TypeScript：严谨的“魔法菜谱”与“安检员” ​

它是什么？ TypeScript（简称 TS）其实就是 JavaScript 的“威力加强版”或者说是“严厉的班主任版”。它是由微软（Microsoft）发明的一种编程语言。它和 JS 最大的区别就在于两个字：类型（Type）。

💡 课外小知识：为什么 JavaScript 会被吐槽？ 你知道吗？JavaScript 当年是被它的发明者在短短 10 天内赶工写出来的！因为它太随性了，所以非常容易出错。比如在 JS 里，你可以让数字 1 加上文字 "1"，它不会报错，而是会得出一个奇葩的结果 "11"。如果你不小心把英雄的攻击力拼写成了 hero.attckPower（少了个a），JS 在你写代码的时候完全不会提醒你，直到你真正运行程序，程序“砰”地一声崩溃了，你才会发现。这就好比做菜时不看菜谱，盐和糖乱放，直到顾客吃进嘴里吐出来，你才知道做错了。

为什么我们要用 TypeScript？尤其是为什么在处理 AI 大模型时必须用它？ 这是本节课的一个核心知识点！ 大语言模型（LLM）是非常聪明的，但它们有一个致命的缺点——“幻觉”（Hallucination）和“随性”。大模型本质上是一个概率预测机器，它喜欢用自然语言自由发挥。

假设我们的系统问大模型：“请告诉我亚瑟的胜率是多少？” 我们期望系统收到的回复是一个纯粹的数字，比如：0.55。 但是，大模型今天心情好，它可能会回复你："亚瑟的胜率非常不错哦，大约是百分之五十五！" 或者 "0.55%"。 如果我们的程序还在傻乎乎地用这个结果去进行数学计算（比如 0.55 + 0.1），程序瞬间就会崩溃，因为你不能拿一段汉字去加减乘除！

这就是 TypeScript 大显身手的时候了！TS 允许我们定义严格的**“接口”（Interface）**。我们可以写下铁律：

typescript
interface 英雄数据 {
  名字: string; // 必须是文字
  胜率: number; // 必须是数字，绝不能是文字！
}

3. MCP SDK：官方认证的“万能翻译机” ​

它是什么？ SDK 的全称是 Software Development Kit（软件开发工具包）。你可以把它想象成乐高积木官方推出的一套“带电机的特殊零件包”。

为什么我们要用它？ 我们要让我们的 Node.js 程序和 Claude 这样的大模型聊天，这中间涉及到非常复杂的底层通信协议（怎么发消息、怎么确认收到、怎么处理网络中断等等）。如果我们从零开始自己写这些通信代码，那难度不亚于自己从头造一辆汽车。 而 @modelcontextprotocol/sdk 就是官方为我们准备好的“万能翻译机”。我们只需要调用它里面写好的简单命令，就能瞬间完成复杂的底层通信。这就像是你买了一辆车，不需要知道发动机里的活塞是怎么运动的，你只需要知道怎么踩油门和打方向盘就行了。

别被这些英文吓倒，我来给你通俗地翻译一下这些校规：

  • "target": "ES2022"：翻译目标版本。我们要求把代码翻译成 2022 年最新潮的 JavaScript 语法，而不是老掉牙的古代语法。
  • "module": "NodeNext"：模块化标准。规定了我们的代码文件之间互相借用东西（import/export）时使用的最新暗号。
  • "outDir": "./dist" 和 "rootDir": "./src"：这非常重要！src（source）是我们的“后厨”，我们写的源代码都在这里；dist（distribution）是“出餐口”，翻译好的、可以直接端给客人吃的代码会放在这里。
  • "strict": true：最高级别的严格模式！开启！ 任何一点类型错误、变量没定义的情况，班主任都会立刻打手心报错。这能帮我们在萌芽阶段掐死 99% 的 Bug。

第三章：画个大饼——“王者导师”的系统架构大解剖 ​

经过上面一顿操作，我们的开发环境终于搭好了！在真正开始写王者荣耀的逻辑之前，就像盖楼必须要有设计图一样，我们得先画个草图，看看这个“王者导师”肚子里到底装了啥。

来，看下面这张高大上的系统架构图：

（图：王者导师的肚子里分为：大脑通信层、静态资料库、动态技能包）

根据我们上一篇文章讲过的 MCP 协议核心概念，我们将整个系统完美地划分为了三个主要区域。为了让你秒懂，我们继续用**“开餐厅”**来打比方：

1. Server Core（前台接待与通信层）：跑腿的传菜员 ​

这是整个系统的入口。它不负责做菜，也不负责写菜单。它的唯一工作，就是站在大门口，负责和外部的 AI 大模型（比如 Claude）进行沟通。 大模型发来点餐需求（Request），Server Core 接收下来；后厨把菜做好了（Response），Server Core 负责端出去交给大模型。我们前面安装的 @modelcontextprotocol/sdk 就是用来武装这个前台的。

2. Resources 模块（静态资料区）：餐厅的秘密储藏室 ​

在 MCP 的概念里，Resources（资源）指的是只读的、静态的数据。 在我们的王者导师系统里，什么东西是静态的呢？当然是**《王者荣耀英雄大全》和《装备图鉴大全》**！比如亚瑟的基础血量是多少，破军增加多少物理攻击力。 这些数据就像是餐厅储藏室里的食材和菜谱大全。大模型如果对某个英雄不熟悉，它可以随时通过 MCP 协议来读取这些 Resources，临时抱佛脚，疯狂恶补王者知识。

3. Tools 模块（动态技能区）：后厨的超级大厨 ​

Tools（工具/技能）是 MCP 中最强大的部分，它指的是可以执行具体动作、进行动态计算的函数。 如果说 Resources 是死记硬背的课本，那么 Tools 就是能帮你解数学题的计算器。 在王者导师里，我们将开发三个超级大招（Tools）：

  • “看阵容”：大模型把敌我双方的 5 个英雄名字传过来，Tool 运行一套复杂的算法，分析出阵容的优劣势。
  • “算装备”：根据当前的对局时间、经济差，动态计算出下一件最应该买什么装备。
  • “防Gank”：分析打野的路线，给出防抓预警。 这些都是需要 CPU 去实时计算的逻辑，它们组成了餐厅里真正挥洒汗水的“后厨”。

对应的，我们要在刚才建好的文件夹里，手动创建几个新的文件夹和文件，把这三个区域划分好。最终我们的项目目录会长这样（现在你可以先把这些空文件夹建好）：

第四章：见证奇迹的时刻——跑一个“Hello World”压压惊 ​

纸上得来终觉浅，绝知此事要躬行！ 现在，打开你最喜欢的代码编辑器（强烈推荐使用 Visual Studio Code (VS Code) 或者 Trae），在 src 文件夹下创建一个名为 index.ts 的文件。

我们将在这里写下我们 AI 魔法生涯的第一段咒语。这就像是新餐厅开业前的试营业，我们要让系统跑起来，向世界宣告：“我来了！”

请把下面这段代码原封不动地复制到 src/index.ts 中：

typescript
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

// 1. 建个前台接待处（实例化 Server 对象）
const server = new Server(
  {
    name: "hok-mentor-server",
    version: "1.0.0",
  },
  {
    capabilities: {
      resources: {},
      tools: {},
    },
  }
);

// 2. 准备开门营业的启动仪式
async function main() {
  // 创建一个基于标准输入输出的通信管道
  const transport = new StdioServerTransport();
  
  // 将前台接待处与通信管道连接起来
  await server.connect(transport);
  
  // 向上级（开发者）汇报启动情况
  console.error("🎉 哇塞！王者荣耀导师 MCP Server 启动成功啦！可以开始连线 AI 啦！");
}

// 3. 剪彩开业，并做好安全防护
main().catch((error) => {
  console.error("糟糕，翻车了，餐厅起火了:", error);
});

🧐 逐行代码大解密（连标点符号都不放过！） ​

我知道，对于小白来说，看到哪怕十几行代码都会觉得头晕。别怕，我保证用小学生都能听懂的话，把每一行代码给你揉碎了讲清楚！

  • 第 1-2 行：招兵买马import ... from ... 就是在说：“我要从外面请专业人士来帮忙。” 我们从官方 SDK 里请来了两位大神：一位是 Server（大堂经理），负责管理整个餐厅；另一位是 StdioServerTransport（超级对讲机），负责和外面的 AI 联络。

  • 第 5-17 行：给大堂经理发胸牌并制定菜单const server = new Server(...) 我们正式雇佣了这位大堂经理。

    • 第一个大括号 { name: "hok-mentor-server", version: "1.0.0" } 是给经理做的胸牌，告诉别人我们叫什么名字，今天是第一代版本（1.0.0）。
    • 第二个大括号 { capabilities: { resources: {}, tools: {} } } 非常关键！这是我们贴在门外的营业执照能力清单（Capabilities）。我们在向 AI 宣告：“本店有能力提供资源（resources）和工具（tools）哦！”虽然现在这两个大括号里还是空的（意味着我们还没把具体的英雄数据和算法放进去），但这就像是新店开张挂出的横幅：“敬请期待！”

  • 第 20 行：async function main() 我们定义了一个名叫 main（主要）的启动仪式。注意前面的 async（异步）关键字。为什么需要它？因为开门营业、接通网络是需要花时间等待的。async 允许我们在代码里使用 await（等待），这就像是告诉电脑：“这件事有点慢，你耐心等一下，别急着往下走。”

  • 第 22 行：const transport = new StdioServerTransport();（核心知识点预警！） 这是整个代码里最巧妙的设计！什么是 Stdio？它的全称是 Standard Input/Output（标准输入输出）。

    💡 课外小知识：为什么不用普通的 HTTP 网址？ 平时我们上网看网页，用的都是 HTTP 协议，就像是通过邮局寄信。但是，我们的 MCP Server 通常是和电脑上的本地 AI 客户端（比如 Claude Desktop）配合使用的。如果用 HTTP，我们要开端口，可能还会遇到防火墙拦截，非常麻烦。 而 Stdio 就像是在 AI 客户端和我们的 Node.js 程序之间，直接拉了一根隐形的真空管道！AI 把需求扔进管道的入口（stdin），我们的程序处理完，再把结果从管道的出口（stdout）喷射出去。这种方式极其安全、极速，而且完全不需要复杂的网络配置！

  • 第 25 行：await server.connect(transport); 大堂经理（Server）正式拿起了这个超级对讲机（transport），并戴上了耳机。从这一刻起，我们的服务站真正开始倾听 AI 的召唤了。

  • 第 28 行：console.error("🎉 哇塞！...启动成功啦！");（避坑神技！）请注意！请注意！请注意！（重要的事情说三遍） 很多学过一点点 JS 的同学会问：“老师你是不是写错了？平时我们打印成功的消息都是用 console.log，只有报错才用 console.error 啊！为什么你启动成功了还要用 error 呢？” 这是一个无数新手都会踩的惊天大坑！ 还记得我们刚才说的 Stdio 真空管道吗？console.log 的作用，就是把文字丢进那个用来给 AI 传送数据的 stdout 管道里。 如果我们用 console.log("启动成功啦")，这句话就会顺着管道飞到 AI 那里。AI 满心欢喜地以为收到了什么高级的 JSON 格式的王者荣耀数据，结果拆开一看，是一句人类的废话。AI 的解析器瞬间就会崩溃报错！ 而 console.error 呢？它走的是另一根名叫 stderr 的备用管道。这根备用管道 AI 是不看的，它专门用来把文字显示在开发者（也就是你）的黑框框屏幕上。 所以在 MCP Server 开发中，千万千万不要随便用 console.log！想在终端看日志，统统用 console.error！ 这就像是大堂经理用自己的私人手机给你发报喜短信，而没有占用点餐用的公共对讲机频道。

  • 第 32-34 行：main().catch(...) 这是我们的消防预案。我们正式执行 main() 启动仪式。如果在这个过程中发生了任何意外（比如 SDK 有 bug，或者内存爆炸了），.catch 会像一张安全网一样接住这个错误，并用对讲机报告给你：“翻车了！” 防止程序悄无声息地死掉。
