小学生也能懂的AI魔法！王者荣耀AI导师是怎样炼成的？（七）——装上安全气囊：防坑与优化 ​

各位小小魔法师们，欢迎再次回到我们的“王者荣耀AI导师”秘密制造基地！

在前面的六个章节里，我们已经一起大展身手，用代码赋予了AI看懂王者荣耀局势、推荐出装、分析阵容的超能力。现在的AI导师，就像是一个刚刚学会了绝世武功的少年大侠，跃跃欲试地想要去江湖里闯荡一番。

但是，且慢！

真正的江湖（在程序员的黑话里，我们管这叫“生产环境”，Production Environment）可不是我们在自己电脑上过家家（那叫“开发环境”，Development Environment）。在真实的江湖里，充满了各种各样的突发状况和“危险分子”。

如果我们的AI导师就这样毫无防备地走上大街，迎接它的可能不是鲜花和掌声，而是连续不断的“砰砰”撞墙声，最后直接口吐白沫、死机罢工。

为什么会这样呢？因为在真实世界里，我们面临着三大“终极考验”：

第一大考验：乱按键盘的“熊孩子”玩家。比如，玩家不好好打字，非要问：“对面选了吉吉国王和牛魔王，我该选啥？” 我们的数据库里明明只有“孙悟空”和“牛魔”，AI听不懂这些外号，当场傻眼。 第二大考验：偶尔脑子短路的AI。大语言模型虽然聪明，但偶尔也会“抽风”。比如我们让它填入游戏进行了几分钟（需要一个数字），它偏偏给你填个汉字“十分钟”，或者脑洞大开填个“一万分钟”。 第三大考验：成千上万人的疯狂提问（高并发）。如果你的AI导师太受欢迎，全班同学、全校同学甚至全国的玩家都在同一秒钟跑来问问题，你的电脑硬盘会被翻烂，直接累冒烟。

为了让我们的AI导师不仅武功高强，还能“皮糙肉厚”、刀枪不入，今天，我们就来给它穿上一件无敌铠甲，装上最先进的“安全气囊”，并且给它的大脑升个级！

准备好了吗？我们要开始写出真正大师级的代码了！

1. 请个最严厉又最聪明的保安：Zod 的进阶魔法 ​

大家还记得我们在之前的章节中请来的那位名叫 Zod 的保安吗？当时我们只是让他做一些最基础的工作，比如检查一下来访者是不是带了“名字”这个牌子，带的是不是“字符串”（文字）。

但在真实的战场上，这种基础检查远远不够。玩家的输入是千奇百怪的。我们需要给 Zod 保安升级装备，让他学会两项高级魔法：.transform()（变形术）和 .refine()（火眼金睛）。

1.1 使用 .transform() 施展“变形术”：搞定各种奇葩外号 ​

在王者荣耀的圈子里，大家都有自己的一套“黑话”。

  • 没人管“鲁班七号”叫全名，大家都叫他“小卤蛋”或者“小短腿”。
  • “孙悟空”通常被称为“猴子”或者“吉吉国王”。
  • “孙尚香”是大名鼎鼎的“大小姐”。
  • “牛魔”经常被错叫成西游记里的“牛魔王”。

如果我们的程序死板地去字典（heroes.json）里查“吉吉国王”，肯定是查不到的。程序查不到就会报错，报错就会死机。

这时候，我们就需要用到 Zod 的 .transform() 方法了。它的作用就像是一个同声传译翻译官。不管玩家嘴里蹦出来的是什么方言土语，在数据进入我们的核心代码之前，这个翻译官都会立刻把它转换成标准普通话（官方英雄名称）。

让我们来看看这段神奇的变形术代码是怎么写的：

typescript
import { z } from "zod";

// 第一步：我们先在保安亭里挂一个小本本，也就是一个外号翻译字典。
// Record<string, string> 是 TypeScript 的语法，意思是这是一个对象，
// 它的左边（标签）是文字，右边（真正的内容）也是文字。
const HERO_ALIASES: Record<string, string> = {
  "牛魔王": "牛魔",
  "猴子": "孙悟空",
  "吉吉国王": "孙悟空",
  "卤蛋": "鲁班七号",
  "小短腿": "鲁班七号",
  "大小姐": "孙尚香",
  "老亚瑟": "亚瑟",
  "鱼": "庄周",
  "黄大仙": "太乙真人"
  // 你可以在这里无限添加你和小伙伴们知道的黑话...
};

// 第二步：给保安升级，教会他使用变形术
const HeroNameSchema = z.string().transform((val) => {
  // val 就是玩家或者 AI 传过来的原始名字，比如 "吉吉国王"
  
  // 我们去翻译本上查一查，有没有这个外号？
  const officialName = HERO_ALIASES[val];
  
  // 如果翻译本上有，就返回官方大名（比如 "孙悟空"）
  // 如果翻译本上没有，就原封不动地返回原来的名字（也就是 val 本身）
  return officialName || val;
});

// 第三步：把升级后的保安安排到出装推荐的大门上
export const RecommendBuildSchema = z.object({
  heroName: HeroNameSchema.describe("你要查哪个英雄？支持输入常见外号哦！"),
});

详细解密： 这段代码的精妙之处在于，我们的核心逻辑（比如去数据库查出装的函数）永远不需要知道外号的存在。 当玩家输入“给我查一下吉吉国王的出装”，大模型把“吉吉国王”发给我们的 MCP 服务器。 Zod 保安在门口一把拦住，用 .transform() 扫了一眼，瞬间把“吉吉国王”变成了“孙悟空”。 然后，我们的核心程序高高兴兴地拿着“孙悟空”去查资料，完美命中！这就像是在水管的入口装了一个超级净水器，流进屋子里的水永远是干干净净的。

1.2 使用 .refine() 练就“火眼金睛”：严防死守逻辑漏洞 ​

光会翻译还不够，保安还得会抓逻辑错误。

假设我们有一个功能是分析当前局势，需要 AI 告诉我们游戏已经进行了多少分钟。AI 如果抽风了，传过来一个负数 -5，或者传过来一个 999 分钟。虽然它们都是数字（Number），符合基础的数据类型检查，但它们在现实中是绝对不可能发生的。

一局王者荣耀怎么可能打 999 分钟？那手机早就烧成一块砖头了！如果不拦截这种离谱的数据，我们的局势分析算法就会算出极其荒谬的结果（比如建议你购买 100 把破军）。

为了防备这种情况，我们要用到 .refine() 方法。Refine 的英文意思是“提炼、精炼”，在这里它的作用是自定义的逻辑审查员。

typescript
export const AwarenessSchema = z.object({
  gameTimeMinutes: z.number()
    // .min() 是 Zod 自带的快捷方法，等同于最简单的 refine
    .min(0, "游戏还没开局呢，时间不能是负数别着急！")
    // .max() 也是快捷方法，限制最大值
    .max(60, "一局打了一个小时？别分析了，赶紧投降或者推水晶去吃饭吧！")
    .describe("当前游戏进行的时间（分钟数）"),
    
  // 让我们来看一个更高级的 .refine() 用法
  // 假设我们需要 AI 传入我方金币数，金币数不能是奇奇怪怪的小数
  gold: z.number()
    .refine((val) => {
      // 检查这个数字是不是整数
      return Number.isInteger(val);
    }, {
      // 如果上面的检查返回 false，就会把下面这句话扔给大模型
      message: "王者峡谷里哪有半个金币的？金币必须是整数！"
    })
    .describe("我方当前拥有的金币数量"),
});

2. 报错的艺术：如何触发 AI 的“自我修正”超能力 ​

既然保安这么严厉，那被拦下的人该怎么办？

在传统的电脑程序里，如果输入错误，程序的反应通常是非常粗暴的：直接弹出一个满屏幕英文的红框（报错提示），然后整个程序“砰”地一声崩溃退出，留下一脸懵逼的用户。这就像你开着车，稍微偏离了一下车道，车子不但没有提醒你，反而直接自爆了！

在 MCP 服务器和 AI 结合的世界里，这种“自爆”是绝对不允许的。如果你的 MCP 服务器崩溃了，正在和你聊天的 AI 大模型就会突然断开连接，聊天框里会出现一个冷冰冰的“工具调用失败”。

我们要学习一种更高级的魔法：优雅的错误处理（Error Handling）。

2.1 为什么要给大模型看错误信息？ ​

这里隐藏着一个关于大语言模型（LLM）的终极秘密武器：Self-Correction（自我修正）。

大模型和传统的死板程序不一样，它是有“思考能力”的。如果你只是把门关上（崩溃），它不知道该怎么办；但如果你能隔着门告诉它：“喂！你刚才送过来的钥匙形状不对，少了一个齿，你去换一把来！” 你们猜怎么着？大模型会真的去检查自己的参数，换一把正确的钥匙重新试一次！

这就像是给你的程序装上了一个超级智能的“安全气囊”。当撞车（参数错误）发生时，气囊不仅能保护程序不死机，还能告诉司机（AI）刚才哪里开错了，让它倒车重开。

（图：这就是自我修正的魔法循环！告诉AI哪里错了，AI会挠挠头，修改参数重新调用你的工具，直到成功为止！）

2.2 Try-Catch：编织一张安全网 ​

在 TypeScript（和 JavaScript）中，我们用来捕捉错误的安全网叫做 try...catch 语句。

  • try 的意思是“尝试去执行一段可能有危险的代码”。
  • catch 的意思是“如果这段代码真的爆炸了，不要炸毁整个程序，而是把爆炸的碎片交给我来处理”。

结合我们上面说的 Zod 保安，当保安发现错误时，他会抛出一个专门的错误，叫做 ZodError。我们需要把这个错误抓住，然后翻译成人类（以及 AI）能听懂的“大白话”。

让我们来看看这段极其关键的“安全气囊”代码：

typescript
import { ZodError } from "zod";

// 这是一个处理大模型调用工具请求的函数
async function handleToolCall(request: any) {
  // 我们把可能有危险的操作放进 try 的安全网里
  try {
    // 1. 让 Zod 保安去检查大模型传过来的参数
    // parse 方法如果发现错误，会直接“扔出”一个 ZodError
    const safeParams = RecommendBuildSchema.parse(request.params);
    
    // 2. 如果能走到这里，说明参数完美无缺！
    // 我们可以放心地去执行查数据库、写逻辑的代码了
    const result = await doSomeMagic(safeParams.heroName);
    
    // 3. 正常返回结果给大模型
    return {
      content: [{ type: "text", text: result }],
      isError: false // 告诉 AI：干得漂亮，没出错！
    };
    
  } catch (error: any) {
    // 危险！有错误被扔出来了！安全网 catch 成功兜住了它！
    
    // 我们来看看这个错误是不是我们的 Zod 保安扔出来的
    if (error instanceof ZodError) {
      // 提取出所有的错误信息，用逗号拼起来
      // 比如："游戏还没开局呢，时间不能是负数别着急！", "王者峡谷里哪有半个金币的？"
      const errorDetails = error.errors.map(e => e.message).join(', ');
      
      console.log(`[保安拦截] 拦截到一次离谱的调用：${errorDetails}`);
      
      // 【敲黑板！这里是全宇宙最重要的一步！】
      // 我们不是让程序崩溃，而是按照 MCP 的规矩，返回一个特殊格式的回复给 AI
      return {
        content: [
          {
            type: "text",
            // 把保安的话原封不动地告诉 AI，语气可以稍微引导一下
            text: `哎呀，你传给我的参数有问题被拦截了：${errorDetails}。请你检查一下用户的输入，或者修改你的参数，重新调用一次工具吧！`,
          },
        ],
        // 这个 isError: true 标记非常非常重要！
        // 它是 MCP 协议里的规定。大模型看到这个标记是 true，
        // 就会立刻启动它的“自我修正”机制，重新思考并再次尝试调用！
        isError: true, 
      };
    }

    // 如果是其他我们意想不到的错误（比如断网了），我们也温柔地告诉 AI
    return {
      content: [{ type: "text", text: `服务器内部发生了一点小意外：${error.message}。请稍后再试。` }],
      isError: true,
    };
  }
}

通过这套机制，我们的 MCP 服务器就像是变成了一个极其耐心的老师。每当 AI 这个学生做错题（传错参数）时，老师不会撕作业本（崩溃），而是把错题圈出来，写上评语（返回带有 isError: true 和详细文字的响应），让学生重新做一遍。

你会惊讶地发现，现在的 AI 极其聪明，通常在收到错误提示的下一秒，它就能自己修改好参数，成功获取数据并回答用户的问题。这就叫真正的“健壮性”（Robustness）！

3. 性能起飞：装上“内存加速器”拯救硬盘 ​

现在我们的服务器已经不会崩溃了，但是它跑得够快吗？

想象这样一个场景：你把做好的王者导师做成了一个对外的服务，分享给了全班 50 个同学。晚上 8 点做完作业，大家同时掏出手机，疯狂向你的 AI 提问。

你的代码逻辑是这样的：每次 AI 需要查询英雄数据，你就使用 fs.readFile 去读取硬盘上的 heroes.json 文件。

对于电脑来说，读取硬盘（我们称之为 Disk I/O，即磁盘输入输出）是一个非常非常缓慢的操作。这就像是你的书桌（CPU 和内存）上没有书，每次你想查一个成语，都要穿过操场跑去对面的图书馆（硬盘），在茫茫书海中找到那本词典，翻开查阅，然后再跑回书桌前写作业。

一个人跑去图书馆可能还好，如果 50 个人同时挤进图书馆找同一本书，图书馆的门槛都要被踩烂了，门卫大爷（操作系统）也会疯掉。你的服务器就会变得卡顿、响应极其缓慢，甚至因为打开了太多文件而报错。

这就是我们在生产环境中必须解决的高并发性能瓶颈。

3.1 什么是“内存缓存”（In-Memory Caching）？ ​

解决这个问题的方法极其简单，但又无比巧妙。

既然这本书（heroes.json）的内容是固定的（至少在下次王者荣耀游戏更新之前是不会变的），我们为什么不派一个人，在每天早上开门的时候，去图书馆把这本书借出来，然后把整本书的内容死记硬背在自己的脑子里呢？

当大脑记住了所有的内容后，后面这 50 个同学再来问问题，我们直接从脑子（内存，RAM）里把答案脱口而出，根本不需要再跑去图书馆（硬盘）了！

读取内存的速度，比读取普通硬盘的速度要快成千上万倍。这就是软件开发中极其重要的概念——内存缓存（Caching）。

（图：把书本内容记在脑子里，下次查就不用翻书了，速度起飞，瞬间化身闪电侠！）

3.2 徒手捏一个缓存系统 ​

在 TypeScript 和 Node.js 中，实现一个最基础的内存缓存简直比吃雪糕还简单。我们只需要利用一个“全局变量”就可以了。

全局变量就像是服务器的一个长久记忆区，只要你的服务器程序不被强行关闭，储存在这里面的数据就会一直存在。

让我们来改造一下读取英雄数据的代码：

typescript
import fs from "fs/promises";
import path from "path";

// 1. 搞个小本本记下来（这就是我们的内存缓存变量）
// 一开始它是空的（null），因为我们还没开始背书
let heroesCache: any = null;

// 这是一个专门负责提供英雄数据的函数
export async function getHeroesData() {
  
  // 2. 每次有人来要数据，我们先摸摸自己的脑袋，看看缓存里有没有？
  if (heroesCache !== null) {
    // 哇！脑子里有货！
    // 我们连一微秒都不耽搁，直接把脑子里的数据扔回去。
    // 硬盘老大哥这时候正在呼呼大睡，根本不用打扰它。
    console.log("[极速模式] 直接从脑子（内存）里读取数据，快如闪电！");
    return heroesCache;
  }

  // 3. 如果走到这里，说明 heroesCache 是 null，脑子里一片空白。
  // 这说明这是服务器刚刚启动，迎接的第一位访客。
  // 没办法，第一次只能老老实实穿过操场去图书馆（硬盘）翻书了。
  console.log("[慢速模式] 脑子里没记住，正在老老实实翻书（读取硬盘）...");
  
  try {
    const filePath = path.join(process.cwd(), "data", "heroes.json");
    // 读取文件内容
    const fileContent = await fs.readFile(filePath, "utf-8");
    // 把文字解析成 JavaScript 可以理解的对象
    const parsedData = JSON.parse(fileContent);
    
    // 4. 【关键步骤】把查到的数据死死地刻在脑子里！
    // 赋值给全局变量 heroesCache。
    heroesCache = parsedData;
    
    console.log("耶！英雄数据已经背在脑子里啦！以后的查询都不用再翻书了！");
    
    // 把数据返回给这第一位苦苦等待的访客
    return heroesCache;
    
  } catch (error) {
    console.error("糟了，去图书馆翻书的路上摔了一跤，没拿到数据：", error);
    throw error;
  }
}
