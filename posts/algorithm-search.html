算法基础：查找算法精讲 ​

第一篇：查找的本质 —— 从大海捞针到精准定位 ​

在计算机科学中，查找（Searching） 是指在特定的数据结构中，根据给定的某个值，确定该值是否存在，或者找到其具体位置的过程。

1.1 核心术语 ​

  • 查询码 (Key)：用来标识一个记录的某个数据项。
  • 平均查找长度 (ASL - Average Search Length)：衡量查找算法效率的主要指标。它代表在查找过程中，需要进行比较的关键字次数的期望值。

    ASL=∑i=1nPi⋅CiASL = \sum_{i=1}^{n} P_i \cdot C_i ASL=​i=1​∑​n​​P​i​​⋅C​i​​

    其中 PiP_iP​i​​ 是查找第 iii 个记录的概率，CiC_iC​i​​ 是找到第 iii 个记录所需的比较次数。

1.2 静态查找 vs 动态查找 ​

  • 静态查找：只查找，不改变数据集。
  • 动态查找：在查找的过程中，可能会向数据集中插入或删除元素。

第二篇：顺序查找 (Linear Search) —— 最朴素的智慧 ​

顺序查找是最简单的查找方法。它从表的一端开始，逐个将记录的关键字与给定值进行比较。

2.1 基础实现 ​

最直观的代码实现如下：

typescript
function linearSearch(arr: number[], target: number): number {
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === target) return i;
  }
  return -1;
}

2.2 优化：引入“哨兵” (Sentinel) ​

在基础实现中，循环每一步都要进行两次判断：i < arr.length 和 arr[i] === target。 通过在数组的一端设置“哨兵”，我们可以省去边界检查，从而提高效率。

typescript
function linearSearchWithSentinel(arr: number[], target: number): number {
  const n = arr.length;
  if (n === 0) return -1;
  
  // 暂存最后一个元素，将目标值放入末尾作为哨兵
  const last = arr[n - 1];
  arr[n - 1] = target;
  
  let i = 0;
  while (arr[i] !== target) {
    i++;
  }
  
  // 恢复数组
  arr[n - 1] = last;
  
  // 如果 i 小于 n-1，说明在中间找到了
  // 或者如果最后一个元素本身就是目标，也说明找到了
  if (i < n - 1 || last === target) return i;
  return -1;
}

第三篇：二分查找 (Binary Search) —— 折半的艺术 ​

前提条件：元素必须有序（通常是升序），且必须支持随机访问（数组）。

3.1 核心思想 ​

每次将搜索区间缩小一半。就像在字典里查单词，你会先翻到中间，然后决定是往前还是往后找。

3.2 细节里的魔鬼：边界处理 ​

二分查找的代码看起来简单，但“边界条件”非常容易写错。主要有两种风格：

A. 左闭右闭区间 [left, right] ​

  • 初始化：right = n - 1
  • 循环条件：left <= right
  • 更新：right = mid - 1 或 left = mid + 1

B. 左闭右开区间 [left, right) ​

  • 初始化：right = n
  • 循环条件：left < right
  • 更新：right = mid 或 left = mid + 1

3.3 进阶：防止整数溢出 ​

在计算 mid 时，传统的 (left + right) / 2 在 left 和 right 很大时可能导致加法溢出。 更安全的写法：

mid=left+(right−left)/2mid = left + (right - left) / 2 mid=left+(right−left)/2

或者利用位运算（在某些语言中更快）：

mid=left+((right−left)>>1)mid = left + ((right - left) >> 1) mid=left+((right−left)>>1)

3.4 代码实现（TypeScript 优化版） ​

typescript
/**
 * 标准二分查找 (左闭右闭风格)
 */
function binarySearch(arr: number[], target: number): number {
  let left = 0;
  let right = arr.length - 1;

  while (left <= right) {
    // 防止溢出的安全写法
    const mid = left + Math.floor((right - left) / 2);
    
    if (arr[mid] === target) {
      return mid; // 找到目标
    } else if (arr[mid] < target) {
      left = mid + 1; // 目标在右半部分
    } else {
      right = mid - 1; // 目标在左半部分
    }
  }
  return -1; // 未找到
}

第四篇：二分查找的变体 —— 寻找边界 ​

如果数组中有重复元素，我们可能需要找到目标的“第一个”或“最后一个”位置。

4.1 查找第一个等于目标的值 ​

typescript
function findFirstOccurrence(arr: number[], target: number): number {
  let left = 0, right = arr.length - 1;
  let result = -1;
  while (left <= right) {
    let mid = left + ((right - left) >> 1);
    if (arr[mid] >= target) {
      if (arr[mid] === target) result = mid;
      right = mid - 1; // 继续向左找
    } else {
      left = mid + 1;
    }
  }
  return result;
}

第五篇：高级静态查找 —— 寻找更优的比例 ​

5.1 插值查找 (Interpolation Search) ​

如果数据分布非常均匀（比如 1 到 1000），二分查找每次切中点可能不是最优。 插值查找根据目标值在范围内的比例来预测位置：

mid=left+target−arr[left]arr[right]−arr[left]⋅(right−left)mid = left + \frac{target - arr[left]}{arr[right] - arr[left]} \cdot (right - left) mid=left+​arr[right]−arr[left]​​target−arr[left]​​⋅(right−left)

  • 复杂度：对于均匀分布的数据，ASL 接近 O(log(logn))O(\log(\log n))O(log(logn))。
  • 局限性：如果数据分布极度不均，性能可能退化到 O(n)O(n)O(n)。

5.2 斐波那契查找 (Fibonacci Search) ​

利用黄金分割比例（0.618）来切分数组。它要求数组长度满足 Fk−1F_k - 1F​k​​−1。

  • 优点：计算 mid 只需加减法，不涉及乘除法（在古代 CPU 上这很重要）。

5.3 分块查找 (Block Search / Index Sequential Search) ​

将数组分成若干块，每一块内部可以无序，但块与块之间必须有序。

  1. 建立一个索引表，存储每块的最大值和起始位置。
  2. 先在索引表中二分查找确定目标在哪一块。
  3. 在块内顺序查找。
  • 性能：介于顺序查找和二分查找之间。

第六篇：动态查找与哈希查找 —— 效率的巅峰 ​

当数据集频繁变动时，静态数组就不再适用。

6.1 二叉搜索树 (BST) ​

每个节点满足：左子树所有节点 < 根节点 < 右子树所有节点。

  • 理想情况：O(logn)O(\log n)O(logn)。
  • 最坏情况：如果树退化成链表，复杂度变为 O(n)O(n)O(n)。这就是为什么要引入 AVL 树 或 红黑树 进行平衡。

6.2 哈希查找 (Hash Search) ​

这是最接近“直觉”的查找：通过一个哈希函数 H(key)H(key)H(key)，直接计算出存储地址。

  • 理想复杂度：O(1)O(1)O(1)。
  • 核心挑战：哈希冲突
    1. 开放定址法 (Open Addressing)：
      • 线性探测 (Linear Probing)：di=1,2,3...d_i = 1, 2, 3...d​i​​=1,2,3...。简单但容易产生“堆积”现象。
      • 二次探测 (Quadratic Probing)：di=12,−12,22,−22...d_i = 1^2, -1^2, 2^2, -2^2...d​i​​=1​2​​,−1​2​​,2​2​​,−2​2​​...。能有效减少堆积。
    2. 链地址法 (Chaining)：在冲突的位置维护一个链表（Java 的 HashMap 采用此方案）。

6.3 数据库的搜索基石：B+ 树 ​

为什么数据库索引不直接用红黑树？

  1. 磁盘 IO：B+ 树的分叉非常多（通常几百个），树的高度极低（通常 3-4 层就能存储千万级数据），大大减少了磁盘读取次数。
  2. 范围查询：B+ 树的叶子节点通过链表相连，非常适合 WHERE price > 100 AND price < 200 这样的范围查找。

第七篇：多语言实现大荟萃 ​

7.1 Python：简洁的艺术 ​

python
def binary_search_safe(arr: list[int], target: int) -> int:
    left, right = 0, len(arr) - 1
    while left <= right:
        # Python 3 整数不会溢出，但这种写法在其他语言中很重要
        mid = left + (right - left) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

public class SearchUtils {
    public static int binarySearch(int[] arr, int target) {
        int left = 0;
        int right = arr.length - 1;
        while (left <= right) {
            // Java 中推荐使用无符号右移防止溢出
            int mid = (left + right) >>> 1;
            if (arr[mid] == target) {
                return mid;
            } else if (arr[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        return -1;
    }
}

7.2 如何选择？ ​

  • 数据量极小：顺序查找最省事。
  • 数据有序且稳定：二分查找是首选。
  • 数据均匀分布：插值查找能稍微提速。
  • 频繁增删查：红黑树或哈希表。

第八篇：现代视野 —— 向量检索与 AI ​

在 AI 时代，我们不再只是查找“完全匹配”的字符串，而是查找“意思相近”的内容。

  • 向量搜索 (Vector Search)：将文字、图片转换为高维向量（Embedding），通过计算余弦相似度或欧氏距离，在海量数据中找到最接近的目标。
  • 倒排索引 (Inverted Index)：Elasticsearch 的核心。通过单词找文档，而不是通过文档找单词。

第九篇：解题与面试避坑指南 ​

9.1 查找算法的调试技巧 ​

  1. 打印中间变量：在二分查找中，务必打印出每一轮的 left, right, mid 和 arr[mid]。
  2. 测试极端情况：
    • 数组为空。
    • 数组只有一个元素。
    • 目标值在数组开头、末尾。
    • 目标值不在数组中。
  3. 死循环检查：如果 left 和 right 的更新逻辑写错，很容易陷入 left = 0, right = 1 的无限循环。

9.2 面试常见套路 ​

  • 问：二分查找一定要有序吗？
    • 答：不一定。只要数据具有“二段性”（即可以将搜索范围划分为满足条件和不满足条件的两个部分），就可以使用二分。例如寻找旋转排序数组的最小值。
  • 问：哈希查找为什么快？
    • 答：它将查找转化为了计算，利用了数组随机访问 O(1)O(1)O(1) 的特性。

第十篇：实战练习与深度解析 ​

【基础关】 ​

  1. 题目：在包含 1000 个元素的有序数组中进行二分查找，最多需要比较多少次？ 解答：⌈log2(1000)⌉=10\lceil \log_2(1000) \rceil = 10⌈log​2​​(1000)⌉=10 次。

【进阶关】 ​

  1. 题目：为什么在计算二分查找的 mid 时，推荐使用 left + (right - left) / 2？ 解答：当 left 和 right 都是很大的正整数时，直接相加可能超过该数据类型的最大值（溢出），导致结果变为负数或错误值。这种写法能有效避免加法溢出。

【奥数/算法关】 ​

  1. 题目：一个长度为 nnn 的数组，除了一个数字只出现了一次外，其余数字都出现了两次。如何用最优复杂度找到它？ 解答：利用异或 (XOR) 运算。将所有数字异或，相同数字抵消为 0，最后剩下的就是那个只出现一次的数字。复杂度 O(n)O(n)O(n)。

第十一篇：你知道吗？ —— 查找算法的趣味冷知识 ​

  1. “二分”的思想比计算机还老：早在公元前 200 年左右，中国古代数学名著《九章算术》中就提到了类似“折半”的思想。
  2. 哈希表的“生日悖论”：在哈希表中，即使负载因子很低，冲突发生的概率也比你直觉上要高得多。就像在一个 23 人的房间里，有两人生日相同的概率超过 50%。
  3. 世界上最快的“查找”：量子计算中的 Grover 算法。在无序序列中查找目标，经典计算需要 O(n)O(n)O(n)，而量子计算只需要 O(n)O(\sqrt{n})O(√​n​​​)。

结语：在数据的海洋中导航 ​

查找算法不仅仅是代码，它是我们处理信息的一种逻辑模型。从简单的顺序遍历，到复杂的 B+ 树索引，再到如今的向量检索，人类一直在追求更快的速度和更精准的结果。

掌握了查找算法，你就掌握了高效获取信息的钥匙。
