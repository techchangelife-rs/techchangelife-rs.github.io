上回说到，我们要给AI装上一双“手”和一双“眼睛”，让它能帮我们分析《王者荣耀》的局势，甚至在我们连败破防的时候给我们当心理辅导老师。

但你可能马上就要举手提问了：“老师！AI又没有真手，也没有鼠标键盘，它被关在遥远的机房服务器里，它到底是怎么按出大招、怎么查到鲁班七号怕什么刺客的呢？它难道能顺着网线爬过来帮我打游戏吗？”

别急，今天我们就来彻底揭开这个魔术的底牌。准备好你的瓜子、可乐和小本本，我们要讲两个听起来很唬人、英文极其高大上、但其实原理非常简单接地气的词儿：Function Calling（函数调用） 和 MCP协议（万能插头）。

不管你是刚学会加减乘除的小学生，还是对代码一窍不通的纯小白，只要你认真看完这篇文章，我保证你能把这两个概念给别人吹得头头是道！

零、课前思考：被困在玻璃罐里的天才大脑 ​

在正式开始之前，我们要先纠正一个关于AI的巨大误区。

很多人以为，当我们在微信或者网页里跟AI聊天时，AI是在“上网”帮我们找答案。其实根本不是！

你可以把现在的AI（比如ChatGPT、Claude、Kimi）想象成一个**“被困在真空玻璃罐里的绝世天才”**（学术界管这叫“缸中之脑”）。 这个天才在进玻璃罐之前，背下了人类历史上所有的书、所有的网页、所有的游戏攻略。所以你问他李白怎么出装，他能滔滔不绝。

但是！他有一个致命的弱点：他没有手，没有脚，而且他的记忆永远停留在进罐子的那一天！

如果你问他：“天才，请问我现在这局王者荣耀，对面的打野在哪儿？” 天才只能在罐子里干瞪眼：“大哥，我连罐子都出不去，我怎么知道你手机屏幕上显示了啥？”

那么，我们该怎么让这个被困在罐子里的天才，不仅能“知道”外面发生了什么，还能“动手”帮我们查资料、甚至发指令呢？

这就是我们要学的第一个魔法：Function Calling。

第一章：AI魔法的开端——Function Calling（一场精密的接力赛） ​

很多初学者觉得 AI 调工具是某种黑科技，以为AI真的长出了无形的手去敲击键盘。其实真相非常朴素：AI 依然是个只能“吐字”的语言模型。

它干活的套路，完全是一场你画我猜的“传纸条”接力赛！

（图：用户提问 -> AI输出指令 -> 程序员执行 -> 告诉AI结果 -> AI回答用户）

1.1 传纸条游戏：军师（AI）是如何帮你查资料的？ ​

让我们回到小学的课堂上。 假设你（用户）坐在教室第一排，正在偷偷玩《王者荣耀》。你突然发现对面选了一个特别恶心的蔡文姬，回血跟喝水一样。你慌了。 这时候，你想要向坐在教室最后一排的学神“小AI”求助。 但是，小AI离你太远了，而且他没有手机，没法自己查资料。不过，你的同桌“小程”（程序员写的代码）有手机可以查资料。

于是，一场五步接力赛开始了：

  1. 第一棒（你发出求救）：你写了一张纸条传给后排的小AI：“救命！对面选了蔡文姬，我该拿什么英雄克制她？”
  2. 第二棒（AI想对策并写指令）：小AI收到纸条，心想：“蔡文姬？我记得以前学过，但我得查查最新的克制数据才严谨。不过我没手机啊！” 于是，小AI 停止和你说话，转而写了一张极其规范的纸条传给你的同桌小程。纸条上写着：“嘿！小程，快帮我用你手机里的 查英雄克制 功能，搜索一下 蔡文姬 ！”
  3. 第三棒（程序员干活）：同桌小程（也就是我们写的代码程序）拿到了这张纸条，立刻打开手机里的王者营地（或者数据库API），输入“蔡文姬”，查到了结果：“蔡文姬怕甄姬、王昭君，还有制裁之刃”。
  4. 第四棒（把结果扔回给AI）：小程把查到的结果抄在纸条背面，又传回给了后排的小AI。
  5. 第五棒（AI邀功与回答）：小AI拿到结果，恍然大悟，马上用非常温柔、像模像样的语气给你写了最后一张纸条：“亲爱的召唤师，遇到蔡文姬不要慌！我强烈推荐你选甄姬或者王昭君去冰冻她，对了，千万别忘了提醒射手出制裁之刃哦！”

看懂了吗？划重点了！！！ AI 根本就没有自己去翻数据库，也没有自己去点鼠标！它只是非常聪明地告诉你：“我需要什么数据，请你（代码）帮我查一下。”

这就是 Function Calling（函数调用）的本质！AI 不执行动作，AI 只生成“执行动作的说明书”，然后让代码去执行。

1.2 核心解密：自然语言是怎么变成机器指令的？ ​

听完上面的故事，你可能会觉得：“这不挺简单的嘛！” 但如果你是那个同桌“小程”（也就是计算机），你就会发现一个巨大的麻烦。

人类说话是非常随意的（这叫自然语言）。 你可能会说：“帮我查查蔡文姬。” 你也可能会说：“对面那个坐摇摇车的奶妈怎么打？” 你甚至可能打错字：“查查菜文姬”。

但是计算机程序是个彻头彻尾的“死脑筋”。计算机的函数通常长这样： get_counter_hero(hero_name="蔡文姬") 如果你给计算机输入“那个坐摇摇车的奶妈”，计算机会直接崩溃死机，给你弹出一个巨大的红色Error。

所以，Function Calling 最牛逼的地方，就在于它能把人类乱七八糟的“自然语言”，精准地翻译成计算机能看懂的“结构化数据”。

AI 是怎么做到的呢？这就不得不提到计算机世界里的通用语言：JSON。

1.3 JSON 与 JSON Schema：约束AI的“紧箍咒” ​

什么是 JSON？ 你可以把 JSON 想象成一个有很多格子的日式便当盒。每个格子里只能放特定的东西，而且格子上都贴着标签。 比如，一个用来查询英雄的 JSON 便当盒长这样：

json
{
  "动作": "查询克制英雄",
  "英雄名字": "蔡文姬"
}

什么是 JSON Schema？ 既然 JSON 是便当盒，那 JSON Schema 就是便当盒的制造图纸（或者叫填空题的答题卡）。 我们要让 AI 乖乖地按照图纸来装便当，绝对不能乱装！

让我们来看一张真实的、用来约束 AI 的 JSON Schema 图纸（别怕，我加了超多注释，小学生也能看懂）：

json
{
  "name": "get_counter_hero",
  "description": "当用户在王者荣耀中遇到打不过的敌方英雄时，调用此工具获取克制方案。",
  "parameters": {
    "type": "object",
    "properties": {
      "enemy_hero": {
        "type": "string",
        "description": "敌方英雄的名字，例如：鲁班七号、蔡文姬。注意：如果用户说的是外号（如小短腿、奶妈），请你先翻译成官方全名！"
      },
      "my_role": {
        "type": "string",
        "enum": ["法师", "射手", "打野", "辅助", "对抗路"],
        "description": "玩家想玩的分路位置"
      }
    },
    "required": ["enemy_hero"]
  }
}

我们来拆解一下这张“图纸”的神奇之处：

  1. name (工具名字)：告诉计算机，AI 想用哪个工具。
  2. type: "string" (数据类型)：这就是教导主任的戒尺！它规定了“英雄名字”必须是一串文字（字符串）。如果 AI 脑子抽风填了个数字 123 进去，程序直接拒收！
  3. enum (枚举，选择题)：这是防止 AI 乱说话的绝招。我们规定 my_role 只能从那五个分路里选。如果用户说“我想玩中单”，AI 就会聪明地把它转换成官方词汇 "法师"。如果 AI 敢填 "快乐风男"，这张纸条就会被撕毁！
  4. required (必填项)：规定 enemy_hero 是带星号的必填项。就算天塌下来，AI 也必须填上敌方英雄的名字才能交卷。

划重点：最神奇的 description（描述） ​

你看上面代码里的 description，是不是觉得像是在用大白话跟 AI 聊天？ 没错！这才是 Function Calling 的灵魂！ AI 根本看不懂底层的 C++ 或 Python 代码是怎么写的。它完全是靠阅读这些 description（说明书）来决定要不要用这个工具、以及怎么用这个工具的。

比如我们在 enemy_hero 的描述里写了：“如果用户说的是外号（如小短腿），请你先翻译成官方全名！” 当用户说：“对面小短腿太烦了”，AI 看到说明书后，脑子一转：“小短腿=鲁班七号，我得填鲁班七号。” 于是，AI 完美地生成了：

json
{
  "enemy_hero": "鲁班七号",
  "my_role": "打野"
}

第二章：从诸侯割据到天下一统——MCP协议诞生记 ​

好，既然 Function Calling 这么牛，我们只要学会写 JSON Schema，不就能让 AI 帮我们代打王者了吗？

理想很丰满，现实却非常骨感。在 2023 年到 2024 年初的那段日子里，开发 AI 应用的程序员们（也就是我）几乎被逼疯了。

为什么？因为**“碎片化”**！

2.1 黑暗时代：被API折磨疯的程序员们 ​

想象一下，你是一个热血沸腾的开发者，花了一周时间，写好了一个超级牛逼的“王者荣耀数据查询工具”。 你按照 OpenAI (ChatGPT) 的规矩，写了一套 JSON Schema，对接得很完美。

第二天，你的老板对你说：“哎呀，听说最近 Anthropic 的 Claude 模型特别聪明，打游戏更有天赋，你把我们的工具接到 Claude 上吧！” 你一看 Claude 的开发文档，差点吐血：Claude 传纸条的格式，跟 ChatGPT 完 全 不 一 样！ChatGPT 要用红色的纸，Claude 非要用蓝色的纸，而且折纸飞机的方法都不同！

你只好咬着牙，把代码重写了一遍。

第三天，老板又来了：“最近国产的 Kimi 模型降价了，免费！咱们把工具接给 Kimi 吧！” 你打开文档一看，好家伙，Kimi 传纸条的规矩又换了！

这简直就像回到了十年前的手机充电线时代：

  • 你买个诺基亚，得用圆头针充电器。
  • 你买个摩托罗拉，得用扁头充电器。
  • 你买个苹果，得用宽扁的 30 针充电器。 去朋友家做客手机没电了，根本借不到能用的充电线！这谁顶得住啊？

2.2 救世主降临：MCP（万能插头协议）到底是个啥？ ​

就在全天下程序员都在骂娘的时候，Anthropic（开发 Claude 的那家公司）站了出来，大手一挥：“别折腾了！大家天天这么改代码太浪费生命了。咱们坐下来，制定一个全天下统一的标准接口吧！”

这个统一的接口标准，就叫 MCP (Model Context Protocol，模型上下文协议)。

为了让你一秒听懂，请看下面这张图：

（图：MCP就像USB Type-C接口，一头连着王者荣耀数据，另一头插上任何大模型都能用！）

MCP 就像是如今的 USB Type-C 万能接口！

有了 MCP，我们马上要开发的“王者荣耀导师”，只需要按 MCP 的标准写一次代码。 写完之后，不管你是用 ChatGPT、Claude、Gemini，还是你自己电脑里跑的开源小模型，只要这个 AI 客户端支持 MCP（就像电脑身上有 Type-C 接口一样），咔哒一下插上去，立马就能用！立刻变身王者大神！

这就叫“一次编写，到处运行”（Write Once, Run Anywhere），是程序员毕生的追求！

2.3 拆解MCP的“三头六臂”：核心架构深度揭秘 ​

那么，这个神奇的 MCP 插头里面，到底装了什么东西呢？ 它其实包含了三个最核心的引脚，我们称之为“MCP三大法宝”。只要你掌握了这三样东西，你就能让 AI 无所不能。

法宝一：Resources（静态资源）—— 给 AI 一座黄金屋 ​

这是什么：你可以把它理解为 AI 的随身U盘或者图书馆。 怎么用：AI 是没有最新知识的。通过 Resources，我们可以把《王者荣耀 S35 赛季最新装备属性表》、《王者荣耀所有英雄背景故事》像 PDF 一样直接塞给 AI。 特点：它是只读的。AI 只能看，不能改。 举个栗子：当你在聊天框里输入 mcp://hok/patch_notes/v35 时，AI 就瞬间阅读了整个赛季的更新公告，然后告诉你：“这赛季破甲弓削弱了，射手很难受。”

法宝二：Tools（工具）—— 给 AI 装上加特林机械臂 ​

这是什么：这其实就是我们第一章讲的 Function Calling 的进化完全体！ 怎么用：如果说资源是让 AI “看”，那工具就是让 AI “做”。 特点：它能接收参数，去执行动作，然后把结果返回来。 举个栗子：我们给 AI 提供一个叫 calculate_win_rate(my_team, enemy_team) 的工具。AI 就会把两边的阵容扔进去，工具算完之后告诉 AI：“我方胜率只有 30%，建议重开。”

法宝三：Prompts（人设面具）—— AI 的终极 Cosplay ​

这是什么：这是用来一键切换 AI 性格和场景的模板。 怎么用：打游戏嘛，有时候我们需要鼓励，有时候我们需要被骂醒。我们可以提前写好几个面具。 举个栗子：

  • 面具A：“暴躁电竞教练”。你一选亚瑟打野，AI 直接开喷：“你这选的是什么阴间东西？想掉分直说！”
  • 面具B：“温柔知心大姐姐”。你连败了，AI 会说：“没关系的召唤师，这把是队友太坑了，你已经做得很棒了，喝口水休息一下吧~” MCP 把这些面具标准化了，无论你插在哪个 AI 上，它都能完美还原这种性格！

2.4 极客时间（选修课）：MCP 底层到底是怎么通信的？ ​

(注：这部分有点点硬核，如果你是纯小白可以跳过，如果你想在同学面前装个大的，请熟读背诵！)

你可能会好奇，这个“万能插头”插上去之后，数据在里面到底是怎么流动的？ 答案是：JSON-RPC 协议 + stdio（标准输入输出）。

什么叫 JSON-RPC（Remote Procedure Call，远程过程调用）？ 这就像是点外卖。

  1. AI 客户端（你） 打电话给 MCP 服务器（外卖店）：“喂，我要一份黄焖鸡米饭（调用 get_hero 工具），不要香菜（参数 hero="蔡文姬"），我的订单号是 001（id: 1）。”
  2. MCP 服务器（外卖店） 做好饭后，派骑手送过来：“你的黄焖鸡好了（返回结果），对应订单号 001（id: 1）。”

通过这个唯一的订单号 id，AI 就永远不会把查询蔡文姬的结果，和查询鲁班的结果搞混了。

那什么是 stdio 呢？ 传统的网络请求（HTTP）就像是打电话，需要拨号、连接互联网。 而 stdio（Standard Input/Output）就像是两个人坐在同一张桌子上，直接把纸条滑给对方！ 这就意味着，我们的 MCP 服务器可以完全运行在你的本地电脑上！不需要联网，不需要经过任何中间服务器，极其安全，极其快速！你的王者战绩只有你自己和本地的 AI 知道，绝对不会泄露给别人！

第三章：大一统的未来——为什么我们要用MCP来做王者导师？ ​

讲到这里，你应该已经完全明白我们为什么要费这么大劲去学 MCP 了。

在接下来的实战篇中，我们将手把手带你写一个真实的 王者荣耀 MCP Server。

为什么要用 MCP 做？

  1. 降维打击：以前写一个 AI 工具，只能在网页版的 ChatGPT 里用。现在，我们写好这个 MCP Server，你可以把它接入到 Cursor（写代码神器）里让 AI 帮你写王者攻略，也可以接入到 Claude Desktop 里当桌面助手，甚至以后微信支持 MCP 了，你能直接在微信里呼出你的王者导师！
  2. 彻底解耦：王者荣耀的数据是一直在变的。有了 MCP，AI 还是那个聪明的 AI，你只需要在本地更新你的 MCP 工具，AI 就能永远掌握最新的版本密码。

总结与下期预告 ​

好啦，今天这堂干货满满的“小学生 AI 底层原理课”就到这里啦！让我们快速复习一下今天学到的两个装逼词汇：

  1. Function Calling（函数调用）：AI 不是神仙，它没有手脚。它只是通过“传纸条”的方式，把你的自然语言变成了极其严谨的 JSON 填空题，指挥代码去干活。
  2. MCP（模型上下文协议）：为了拯救被各家大模型接口折磨疯的程序员，诞生了这个 AI 界的“USB Type-C 万能插头”。它包含了三大法宝：提供书本的 Resources、提供机械臂的 Tools，以及提供 Cosplay 面具的 Prompts。
